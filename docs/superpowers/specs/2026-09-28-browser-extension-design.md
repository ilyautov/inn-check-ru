# Браузерное расширение: клиппер ручных блоков и проверка ИНН со страницы

Дата: 2026-09-28. Статус: **первая версия сделана** (вопрос пользователя — «может ещё
сделать браузерное расширение? оно поможет?», затем «давай подумаем, что ещё оно может
дать»; по его «выполнять все цели» взят дефолт — пункты 1–3, macOS/Linux, без магазина).
Отступление от черновика: клиппер без разбора страниц — итог вводит пользователь в форме
(страницы результатов реестров за капчей, живых фикстур для разборщика нет); источники —
существующие браузерные `фссп` и `суды`, залоги и Росздравнадзор — после фикстур.

## Зачем

Часть источников — «только браузер»: реестр залогов (reCAPTCHA), лицензии Росздравнадзора
(галочка «Я не робот»), ФИПС/Роспатент (поиска по ИНН нет), суды общей юрисдикции,
сертификаты. Сейчас пользователь смотрит их сам, а результат переносит в ручной блок
(контракт — `references/brauzer.md`, «Контракт ручного блока») и в пакет доказательств
(`evidence_pack.py --добавить`) руками или через агента. Расширение убирает перепечатку и
сохраняет снимок страницы в пакете. Снимок и штамп подтверждают только, что вложение не
менялось после сохранения, — не подлинность страницы и не полноту проверки (как и для
ручных вложений сейчас, `references/brauzer.md`).

## Правила (не меняются)

- Капчу и галочки проходит пользователь. Расширение ничего не нажимает на странице реестра.
- Никаких фоновых запросов к реестрам, тем более с cookie пользователя: это обход антибота
  его сессией. Расширение читает только уже открытую пользователем вкладку, по его клику.
- Права: `activeTab`, `contextMenus`, `nativeMessaging`, `scripting`. Без `host_permissions`
  на все сайты: банк, почта и прочие страницы не читаются, пока пользователь не кликнул.
- ФИО, телефоны, e-mail и адреса физлиц в JSON блока, URL и свободные текстовые поля не
  попадают. Снимок (пункт 1) — только на страницах, где ФИО нет по устройству реестра
  (итог поиска залогов по ИНН, лицензия юрлица); на карточке ФИПС (авторы, заявители-физлица)
  и на страницах судов со сторонами-физлицами снимок не делается — только ручное вложение
  пользователем, как сейчас. Локальное хранение — тоже сбор (ревью Codex, P2).
- Недоступное или не распознанное — «не проверено: схема: …», а не «пусто».
- Manifest V3, иконки только PNG. Ставится распакованным; публикация в Chrome Web Store —
  отдельное решение пользователя.

## Пункты

1. **Доказательство проверки.** Кнопка на открытой странице реестра: снимок видимой части
   (`captureVisibleTab`, PNG) + URL + время → native-хост → `evidence_pack.py --добавить DIR
   файл --источник <id> --url <URL> --дата <ГГГГ-ММ-ДД> [--найдено …]`. Логика пакета и
   штамп времени остаются в Python.
2. **Клиппер ручного блока.** Для трёх сайтов — разборщик итога открытой страницы:
   «найдено N» / «ничего не найдено» / не распознано. Результат — блок по контракту
   (`статус`, `ввод: "браузер"`, `дата_проверки`, `url`, `параметры_поиска`, `найдено`).
   Новый `scripts/manual_block.py` (stdlib) проверяет блок и пишет его в **новую версию**
   fetch-JSON рядом (не в `fetch.json` пакета — это сломало бы хеш манифеста).
   `profiles._состояние_блока` для этого мало (ревью Codex, P1): он не проверяет ИНН, домен
   и полноту — блок с чужим ИНН и `https://example.org/` получает `ok`. Поэтому
   `manual_block.py` дополнительно требует: ИНН в `параметры_поиска` = ИНН fetch-JSON, хост
   `url` — из списка источника, итог — одно из распознанных значений. «Не проверено»
   (капча не пройдена, вход в аккаунт, поиск не завершён, видна часть страниц) **не
   отклоняется, а записывается** и перекрывает прежний `ok` — иначе останется устаревшее
   «проверено».
   Сайты первой версии: reestr-zalogov.ru и Росздравнадзор (лицензии). Для них нужны новые
   дескрипторы в `sources.SOURCES` с `требует: браузер` (сейчас браузерные — только `фссп` и
   `суды`) и сигналы/схемы блоков. ФИПС в клиппер не входит: карточка знака по номеру не
   укладывается в «найдено N / ничего», а одна карточка не означает проверку всех знаков
   компании — остаётся ручной блок.
3. **Проверить ИНН со страницы.** Выделил ИНН в письме, счёте, карточке продавца → пункт
   контекстного меню «Проверить в inn-check-ru» → native-хост запускает
   `fetch_counterparty.py` + `profiles.py`, во всплывающем окне — светофор, причины и
   «не проверено». Движок один (Python); на JS не переписываем. Контрольная сумма ИНН
   проверяется до запуска.

Не берём: фоновый мониторинг (есть `/inn-watch`), разборщики маркетплейсов (ломаются от
редизайна; выделение ИНН в пункте 3 их заменяет), «сеть из РФ» как довод — CLI пользователя
в РФ дотянется до тех же сайтов сам.

## Устройство

```
extension/                 manifest.json (MV3), background.js, popup.html/js,
                           parsers/{zalogi,roszdrav,fips}.js, icons/*.png
scripts/native_host.py     stdlib; протокол native messaging (длина uint32 + JSON);
                           белый список команд: check, clip, evidence — и больше ничего
scripts/manual_block.py    проверка и вклейка ручного блока
scripts/install_native_host.py   пишет манифест хоста для Chrome (macOS/Linux; Windows —
                           реестр, отдельный шаг)
```

Граница доверия хоста (ревью Codex, P1). Данные страницы недоверенные, и хост их так и
принимает:
- сообщение — JSON строгой схемы; команда из белого списка (`check`, `clip`, `evidence`);
- запуск — фиксированный интерпретатор и argv списком, `shell=False`; значения из сообщения
  идут только как отдельные аргументы после проверки;
- ИНН — 10/12 цифр с верной контрольной суммой; источник — из `sources.SOURCES` с
  `требует: браузер`;
- путей в сообщении нет вовсе: каталог пакетов задан в настройках хоста, имена файлов
  создаёт хост, запись через `O_NOFOLLOW` внутри каталога (абсолютные пути, `..` и
  symlink невозможны по построению);
- манифест хоста — точный `allowed_origins` с id расширения; content script к хосту не
  ходит, всё — через service worker, который проверяет `sender` и привязку к клику;
- кадры: длина uint32 проверяется до чтения (свой лимит 16 MiB на вход, ответ ≤ 1 MB —
  лимит Chrome), частичное чтение, EOF, битый UTF-8/JSON — ошибка в ответе, не падение;
  stdout — только протокол, логи — stderr.

Снимок (ревью Codex, P2): `captureVisibleTab(windowId)` снимает активную вкладку окна, а не
заданную. Service worker запоминает `tabId`, URL и `documentId` в момент клика, после снимка
сверяет их снова и при расхождении отменяет операцию. Хост сайта — из списка источника.

Запись и повторы (ревью Codex, P2): `evidence_pack.py --добавить` сохраняет версию до
штампа, неудачный штамп даёт код 1 при уже записанном вложении. У операции есть id; ответ
хоста различает «сохранено», «сохранено, штамп не поставлен», «пакет не найден / повреждён /
занят». Повтор с тем же id дубля не создаёт.

MV3 (ревью Codex, P2): вся логика — в service worker (`contextMenus.onClicked`, native-
вызовы), результат проверки кладётся в `chrome.storage.session` и показывается при
открытии popup (popup может быть закрыт к концу проверки); таймаут хоста — 120 с; отказ
хоста — «хост не установлен / не отвечает» с инструкцией. `activeTab` сохраняется при
переходах в том же origin — поэтому каждое чтение страницы явно привязано к клику.

## Проверка

- Разборщики: фикстуры HTML двух сайтов (сохранённые пользователем страницы, ФИО и
  контакты вычищены) → ожидаемый блок; мутации (убран счётчик, другая вёрстка) →
  «не проверено: схема:», не «пусто».
- `manual_block.py`: без даты/URL, с чужим ИНН, с чужим хостом — отклоняется; «не
  проверено» — записывается и перекрывает прежний `ok`; `fetch.json` пакета не меняется.
- `native_host.py`: команда вне белого списка, лишние поля, ИНН с неверной контрольной
  суммой, строки с управляющими символами — отказ; кадры: длина сверх лимита, частичное
  чтение, EOF, битый UTF-8; повтор операции с тем же id.
- Расширение вне Chrome (Node-тест разборщиков) — без `chrome.*`, с заглушкой.
- Ревью Kimi и Codex, как у каждого блока.
