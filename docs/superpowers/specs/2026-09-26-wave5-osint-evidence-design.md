## Политика доступа к JSON сайтов (новое правило, общее для C)

ЕФРСБ (`bankrot.fedresurs.ru/backend/cmpbankrupts`) и Федресурс (`fedresurs.ru/backend/*`) —
JSON, который дёргает собственная страница сайта; данные публичны по закону (127-ФЗ,
129-ФЗ). Живая проверка 26.09.2026: без заголовка `Referer` — 403, с `Referer` главной
страницы сайта — JSON; от гео не зависит. Правило:
- отправляем тот `Referer`, что отправляет страница самого сайта, и честный `User-Agent`
  проекта со ссылкой на репозиторий — без маскировки под браузер;
- ни капч, ни JS-челленджей, ни ротации IP/UA, ни повторов после отказа: 401/403/429/
  челлендж → «не проверено: антибот» с кодом;
- не больше 2 запросов на источник на одну проверку;
- поведение описано в дескрипторе источника и отключается `INN_CHECK_BEZ_REFERER=1`
  (тогда источник остаётся браузерным, как до 1.13).
Это решение политики проекта, а не утверждение о законности; оно записывается в
KNOWN_LIMITS и CHANGELOG. Калибровка 1.12 уже работала так.

## B1. debtam и taxoffence (сделано)

- debtam — задолженность по налогам, сборам, взносам, пеням и штрафам **на дату
  состояния, без учёта погашения после неё** (паспорт набора). Запись с суммой > 0 →
  сигнал с суммой и датой; «нет записи» сигнал не снимает.
- taxoffence — только решения, вступившие в силу за год, со штрафом, **не уплаченным к
  1 октября** следующего; с недоимкой не складывается. Сигнала не поднимает — факт.
- registerdisqualified **не подключаем**: ИНН организации там — место работы в момент
  нарушения, а не текущее. Сверка текущего руководителя по ФИО уже есть
  (`disqualified-proc.json`).

## C. ЕФРСБ и Федресурс по ИНН

**ЕФРСБ, источник `банкротство`** (сейчас «браузер»). `cmpbankrupts?searchString=<ИНН>`:
- совпадение только по точному ИНН в `pageData[].inn`; нечёткий поиск не используется;
- в карточку: номер дела, статус, дата статуса из `lastLegalCase`, guid. ФИО
  арбитражного управляющего — публичное сведение, но в вывод не берём (не нужно
  для решения);
- сигнал: дело есть и статус не «прекращено»/«завершено» → 🔴 deal-killer; прекращено →
  🟡 факт «было дело, прекращено <дата>»; нет записи → «пусто» (ЕФРСБ отвечает про всех,
  поиск по ИНН полный). Словарь статусов берём из живых ответов, неизвестный статус —
  «не проверено: статус не распознан <код>», а не молчаливое «действует»;
- канарейка: компания с известным делом (из когорты калибровки); фикстура из живого
  ответа.

**Федресурс, новый источник `федресурс`.** `backend/companies?searchString=<ИНН>` → guid
только при точном совпадении ИНН; `backend/companies/<guid>/publications` → сообщения:
- проверяемая компания должна быть **субъектом** сообщения, а не только публикатором:
  намерение кредитора обратиться с заявлением о банкротстве **этой компании** публикует
  кредитор, а собственное сообщение компании-кредитора может быть про чужое
  банкротство. Роль определяем по полям ответа, снятым с живых фикстур (обе стороны);
  не определилась — «не проверено: роль не распознана»;
- аннулированные сообщения не считаются; у каждого — дата публикации;
- выдача постраничная, берём первую страницу: «найдено» допустимо, «намерений нет»
  допустимо только если страница не полная (`total <= limit`), иначе «не проверено:
  выдача усечена»;
- сигналы: намерение обратиться с заявлением о банкротстве компании (🔴 для отсрочки,
  🟡 для остальных профилей с вердиктом), решение о ликвидации (🔴), реорганизация (🟡),
  ЧА ниже УК (🟡); прочее — фактом;
- негативные кейсы в eval: чужой должник, компания-кредитор, аннулированное сообщение,
  усечённая выдача.

Оба источника пишутся в пакет доказательств автоматически (перехват `_http_get`).

## E. Браузерный путь и своя нода

Меняется правило SKILL.md «пользователя капчей не дёргаем» на «не дёргаем без
согласия»: для обязательных источников профиля (суды, ФССП; ЕФРСБ — если JSON
отказал) агент **предлагает** ручной шаг, и только после согласия открывает страницу в
браузере пользователя (Claude in Chrome / Cowork); капчу решает пользователь, агент её не
трогает. Это одобрено пользователем 26.09.2026; изменение — в CHANGELOG.

Контракт ручного блока (`references/brauzer.md` + резолвер):
- поля: `состояние`, `ввод: "браузер"`, `дата_проверки`, `url`, `параметры_поиска`
  (ИНН/название), `просмотрено` (страниц/записей), `найдено` (кратко), `проверил`
  (пользователь подтвердил результат). Без `дата_проверки` и `url` блок не принимается
  как «проверено»;
- `evidence_pack.py --добавить DIR файл --источник суды --url ...` — вложение с хешем;
  если пакет был со штампом, новый манифест получает **новую версию** (`manifest.2.json`
  + свой штамп), прежние манифест и штамп не перезаписываются;
- карты и отзывы: только вручную в браузере, никогда скриптом; только агрегаты
  (рейтинг, число отзывов, дата, период просмотра) и темы как «сообщения пользователей»;
  показывать только при совпадении адреса; в светофор не входит; скриншоты с именами
  авторов в пакет не кладём.

`references/svoya-noda.md` — VPS в РФ, squid с паролем, `INN_CHECK_PROXY`,
`check_access.py --прокси`; раздел «что проверить» (а не «что откроется»: таймаут со
шведского IP не доказывает геоблок); узел видит ИНН.

## B2. warning-list ЦБ, Росстат websbor, `--офлайн`

- warning-list: «ЦБ сообщает о признаках нелегальной деятельности на финансовом
  рынке <категория>, в списке с <дата>» — не «мошенник». Совпадение только по ИНН; ИНН
  есть примерно у 3 000 из 27 264 записей — «нет совпадения» ≠ «не в списке», в
  KNOWN_LIMITS. 🔴 для `предоплата`/`клиент_115фз` как объявленная консервативная
  политика профиля, 🟡 для остальных. Сначала проверить публичный API ЦБ.
- websbor: ОКПО, ОКВЭД факт, ОКФС, обособленные подразделения по ИНН (JSON, нужен
  корень Минцифры — уже есть `install_ca.py`). Факт, без цвета; число ОП — вход для
  дробления.
- `--офлайн`: только кэш и дампы; eval с запретом сокетов. Граница приватности в README:
  в чате ИНН видит провайдер модели; DaData/Checko видят свои запросы; без посредника —
  только CLI/батч без опциональных агрегаторов.
- `check_access.py` получает probe для всех новых источников.

## D. DaData / Checko

Сужено до полей, которых нет у движка: `invalid` (недостоверность, тариф
«Максимальный» — поле недоступно на бесплатном; «поле не отдано тарифом» ≠ «признака
нет») и дисквалификация руководителя. Статус не сверяем: это производная того же ЕГРЮЛ
(правило «два агрегатора, переписавших один реестр, — один источник»). Маппинг
статусов фиксируется в дескрипторе. Контракт по документации, живьём не проверен —
до ключа пользователя так и пишем. ФИО из ответов в пакет — как и из ЕГРЮЛ (публичные
реестровые сведения).

## F. Измеренный светофор (исследование, не резолвер)

Отдельный исследовательский расчёт, `profiles.resolve` не используется (он справедливо
не даст 🟢 без обязательных источников, а подставлять их — подлог):
- **дата проверки** фиксируется: 01.07.2022 (отчётность-2021 опубликована); компании с
  делом, заявленным до неё, исключаются; окно исхода — 01.07.2022…31.12.2024;
- исход называется точно: «дело о банкротстве заявлено в окне» (не «обанкротился»);
  «выжил» = «дела в окне не найдено»;
- классы финансовой части профиля `отсрочка`: «сигналы есть» / «сигналов нет при полном
  покрытии обязательных показателей» / **«не измерено»** (показатель не рассчитан —
  упрощёнка, пропуски); «не измерено» не сливается с «нет сигналов»;
- исключаются банки, страховые, НКО (ОКОПФ в когорте);
- метрики с ДИ и знаменателями: P(«нет сигналов» | дело) — доля ложно-зелёных,
  P(дело | «нет сигналов»), покрытие; обе фазы весов; честно: оценка на той же когорте,
  где калибровались пороги, — не независимая валидация; ЕГРЮЛ-часть не валидирована;
  часть 🔴-сигналов в ретро недоступна → доля ложно-зелёных — оценка сверху;
- `предоплата` не считаем: её вердикт определяют не финансы.

## G. Бенчмарк (последним)

- эталон собирается **из первоисточников** (ЕГРЮЛ, ЕФРСБ, КАД), датируется и
  коммитится до прогона; рубрика дефектов — тоже до прогона;
- отбор: середняки и свежие кейсы, не только витринные компании;
- в выводе **нет долей и рейтинга** — перечень дефектов с причинами; отдельно: ошибка
  факта / функция не поддерживается / источник недоступен;
- сеть, версии, тарифы, время, ручные шаги — по каждому плечу; наше плечо — и с не-РФ, и
  через свою ноду, если она есть; плечо без ключа вычёркивается до прогона;
- повтор нестабильных источников через неделю; каждый чужой дефект — с датой и
  скриншотом, формулировки «на дату прогона».
