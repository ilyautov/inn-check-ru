# Волна 5 — больше источников, доказуемость, измеренный светофор (26.09.2026)

Цель волны: закрыть то, в чём inn-check-ru уступает конкурентам (docs/konkurenty-2026-09.md),
не нарушая правил проекта: без обхода капч, без общего прокси-пула и платных прокси,
«недоступно → не проверено», числа — кодом, ПДн физлиц не собираем.

Вход: разведка источников 26.09.2026 (живые запросы с не-РФ IP, образцы в scratchpad
recon/), сравнение с конкурентами, решения пользователя от 26.09.2026 (карты и отзывы —
да, агрегатами; соцсети людей — не сейчас; слитые базы — никогда).

Новые наборы в `opendata_refresh.py` / `opendata_index.py` (формат индекса тот же:
ИНН → запись, дата выгрузки едет со значением):

| Набор | Размер, частота | Поле в выводе | Семантика |
|---|---|---|---|
| debtam (недоимки, пени, штрафы) | 73,5 МБ, раз в квартал | `дампы_фнс.недоимки` — суммы по налогам | нет записи ≠ «долга нет»: набор публикуется на дату, значение датируется |
| taxoffence | 4,9 МБ, раз в год | `дампы_фнс.правонарушения` — сумма штрафов | за год выгрузки |
| ЦБ warning-list | 10,8 МБ JSON, ежедневно | новый источник `цб_предупреждения`, deal-killer для профилей с деньгами вперёд | совпадение по ИНН, без нечёткого поиска по названию |

Не берём: registerdisqualified — ИНН организации там место работы в момент
нарушения, а не текущее, совпадение по ИНН контрагента дало бы ложный стоп
(обнаружено при реализации); rsmppp (833 МБ, ценность низкая), disqualifiedpersons/massleaders (заброшены с
2021). Реестры МФО/ЖНК/СКПК ЦБ (XLSX) — вторым шагом, если понадобится профиль
«клиент_115фз».

`--офлайн` у `fetch_counterparty.py` и `batch_check.py`: только кэш и дампы, ни одного
сетевого запроса (проверяется eval'ом с запретом сокетов). В `_сеть` — «офлайн».

Честная граница в README/KNOWN_LIMITS: в режиме чата ИНН видит провайдер модели; без
посредника работает только CLI/батч; сетевые источники ФНС видят свой запрос (это
госорган-первоисточник, а не третье лицо).

## C. Федресурс по ИНН

Разведка: `GET fedresurs.ru/backend/companies?searchString=<ИНН>` → guid;
`GET /backend/companies/<guid>/publications?...` → сообщения. Главная страница под
Qrator; backend с Referer отдаёт JSON без челленджа.

Правила:
- если backend вернул челлендж/401/капчу — «не проверено: антибот», без обхода,
  без ротации, без эмуляции браузера;
- сообщения фильтруются по `publisher.guid == guid компании`: выдача содержит сообщения,
  где компания лишь кредитор;
- сигналы: намерение обратиться с заявлением о банкротстве (🔴 для отсрочки/предоплаты),
  решение о ликвидации (🔴), реорганизация (🟡), снижение ЧА ниже УК (🟡); прочее —
  фактом без цвета; тип сообщения берём из поля ответа, список типов — из живой фикстуры;
- дескриптор в `sources.py` с контрактом полей и канарейкой (компания с известными
  сообщениями), фикстура в `eval/fixtures/net/`;
- лимит: 2 запроса на проверку, пауза как у остальных источников.

Федресурс не заменяет ЕФРСБ-карточку банкротства (`банкротство` остаётся браузерным);
он добавляет ранний сигнал «намерение».

## D. DaData и Checko как опциональные источники

- `дадата`: `POST suggestions.dadata.ru/suggestions/api/4_1/rs/findById/party`,
  `Authorization: Token $DADATA_API_KEY` (бесплатно до 10 000 запросов/сутки). Берём
  `state.status`, `state.liquidation_date`, `invalid`, `management`, `state.actuality_date`.
- `checko_карточка`: тот же ключ `CHECKO_API_KEY`, что у графа, эндпоинт v2/company.
- tier ⚠️ «агрегатор»; сами по себе не поднимают и не опускают светофор ниже ЕГРЮЛ:
  используются для сверки. Расхождение с ЕГРЮЛ (статус, недостоверность) — отдельный
  сигнал «источники расходятся» + дата актуальности агрегатора. Когда ЕГРЮЛ «не
  проверено», агрегатор даёт факт с пометкой «один агрегатор, не первоисточник» — 🟢 на
  нём не выдаётся (правило 1.12.2 сохраняется).
- Нет ключа → «не проверено: ключ не задан (бесплатно: …)», без ошибки.
- Контракт — по документации на 26.09.2026, живьём не проверен (ключей у разработки
  нет): так и пишется в дескрипторе; канарейка включается при наличии ключа.
- Ключи — только из env / user_config .mcpb, маскируются в URL и заголовках пакета
  доказательств (заголовки мы не пишем вовсе).

## E. Браузерный путь и своя нода

`references/brauzer.md` + шаг 4 SKILL.md:
- суды (kad.arbitr.ru), ФССП, ЕФРСБ, реестр залогов, bi.do, Вестник: агент с браузером
  (Claude in Chrome, Cowork) открывает страницу поиска, **капчу решает пользователь**,
  агент читает результат и заполняет блок источника вручную: состояние, дата, URL,
  что увидено. Блок помечается `ввод: браузер` и tier как у первоисточника;
- в пакет доказательств — `evidence_pack.py --добавить DIR файл --источник суды
  --url ...`: скриншот или сохранённая страница с хешем в манифесте (пакет с штампом
  после добавления штампуется заново);
- карты и отзывы (решение пользователя 26.09.2026): карточка организации на Яндекс
  Картах / 2ГИС, Dream Job, otzovik — **только агрегаты**: рейтинг, число отзывов, дата,
  2–3 повторяющиеся темы жалоб своими словами; имена авторов и тексты отзывов не
  сохраняем; сопоставление с ИНН по адресу и названию — tier ⚠️, в светофор не входит
  (сигнал «репутация» — факт, не цвет). Массовое выкачивание и API без ключа — нет;
- «своя нода»: `references/svoya-noda.md` — VPS в РФ, squid с паролем, `INN_CHECK_PROXY`,
  проверка `check_access.py --прокси`; что откроется (ЕИС, torgi, ФАС, Минюст,
  pb-детали) и что узел видит ИНН. Общей ноды у проекта нет и не будет.

## F. Измеренный светофор

Честный объём: полный светофор ретроспективно не восстановить — ЕГРЮЛ-флаги
(недостоверность, массовость) на 2021 год из открытых данных не получить. Проверяем
то, что можно:
- финансовая часть вердикта профилей `отсрочка` и `предоплата` (сигналы из
  `fin_scoring` → резолвер профиля) на когорте калибровки (2021 → банкротства
  2022–2024), двухфазные веса как в калибровке;
- метрики: доля будущих банкротов, получивших бы 🟢 по финансовой части
  («ложно-зелёный»), доля 🟡/🔴 среди выживших, лифт; ДИ бутстрепом;
- вывод в `references/kalibrovka.md` отдельным разделом «светофор, финансовая часть» с
  явным «ЕГРЮЛ-часть не валидирована».

## G. Бенчмарк

15 ИНН с известным состоянием (действующие крупные, ликвидированные, банкроты, ИП,
компания с недостоверностью) — список из открытых источников с датой. Прогон:
inn-check-ru (CLI), mcp-fns-check (MIT, локально), DaData MCP (если пользователь даст
ключ), Rusprofile (веб, вручную через браузер). Записываем: ответ/отказ, «не проверено»
названо или скрыто, пропуски известных фактов, ложные тревоги, время. Итог —
`docs/benchmark-2026-09.md`: дефекты и их причины; **не** оценка точности.
