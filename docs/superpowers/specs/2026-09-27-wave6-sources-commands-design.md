# Волна 6: новые источники и команды анализа

Дата: 2026-09-27. Решение пользователя: «давай тогда сделаем первые 5 пунктов а потом и 6»
(пункты — из ответа «какие ещё данные мы можем собирать»), плюс «команды на анализ у нас
должны быть разные». Правила проекта не меняются: только открытые реестры о юрлицах и
ИП; без капч, ротаций и повторов; JSON — только тот, что вызывает сама страница сайта,
с её Referer и честным UA; недоступное — «не проверено»; ФИО и контакты физлиц в
репозиторий и отчёты не кладём; сигнал — только по значениям, увиденным живьём.

## Блоки и порядок

1. **«контракты» (Госзатраты).** Фаза «досье». Поля: число и сумма контрактов по 44-ФЗ
   и 223-ФЗ (из `totals` карточки поставщика — `count` в списке контрактов обрезан на
   500), дата и заказчик последнего контракта (первая страница, сортировка `-sign_date`),
   `is_unfair` как есть. Поставщика нет (404) — «пусто: в Госзатратах нет поставщика».
   Сигналов риска нет: контракты — противовес «пустышке», это данные, а не стоп.
   `is_unfair` сигналом не делаем, пока не увидим `true` живьём и не сверим с РНП.
   В отчёте — «зеркало ЕИС», дата свежести = дата последнего контракта в выдаче.
2. **«сро» (НОСТРОЙ).** Фаза «досье», профили «подрядчик», «тендер». Точный ИНН в выдаче
   поиска (поиск — по подстроке ИНН/ОГРН/названия). По каждому членству: СРО, статус
   членства («Является членом» / «Исключен» — полный справочник `dictionaries/get`),
   дата вступления; для действующих — карточка: статус права, уровень ответственности
   ВВ/ОДО, особо опасные, число проверок. ФИО руководителя, специалисты, адрес и телефоны
   не берём. Сигнал 🟡 «сро_право_не_действует» — если членство есть, а статус права
   не «Действует» (другие статусы живьём не видели — показываем текст как есть).
   Отсутствие членства — не сигнал (не всем подрядчикам нужно), а строка в профиле
   «подрядчик»: «если работы требуют СРО (ст. 55.8 ГрК РФ) — проверить вручную».
3. **Лицензии, сертификаты, залоги — браузерный путь.** `references/brauzer.md`: где
   искать, что записать в ручной блок (контракт волны 5: статус, дата, URL).
4. **«домен».** `--домен example.ru`: WHOIS .ru/.рф — дата регистрации, регистратор,
   состояние, `org`/`taxpayer-id`, если открыты. Совпадение `taxpayer-id` с ИНН —
   подтверждение; скрыто — «не проверено», не «чужой».
5. **ФИПС** — разведка поиска по правообладателю; без угаданных API.
6. **Суды общей юрисдикции** — после 1–5.
7. **Команды анализа.** Слэш-команды плагина — тонкие обёртки над существующими
   инструментами: `/inn-check`, `/inn-dossier`, `/inn-batch`, `/inn-watch`,
   `/inn-retro`, `/inn-links`, `/inn-vat`, `/inn-self`. Профиль — аргумент.

Каждый блок: живая сверка → фикстуры → eval с мутациями → ревью Kimi и Codex → коммит.
