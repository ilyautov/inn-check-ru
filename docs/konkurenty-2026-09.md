# inn-check-ru и конкуренты — сравнение на 26.09.2026

Как собрано: три независимых обзора (Codex CLI, Kimi CLI, веб-агент Claude), сводка
Claude, затем критическое ревью сводки Codex и Kimi. Спорные факты перепроверены у
первоисточника; где источники расходятся — так и помечено. Цены — опубликованные на
дату, веб-подписки и API не взаимозаменяемы. Версия проекта — 1.12.2.

## Главный вывод

inn-check-ru конкурентоспособен как **бесплатный и проверяемый слой внутри
AI-агента**. По полноте автоматического досье (суды, ФССП, банкротства, мониторинг
с уведомлениями) он заметно уступает платным сервисам. Прозрачность методики — его
реальное отличие, но **не доказательство, что решение пользователя лучше**: этого
пока не показывал ни один сравнительный тест.

Платные сервисы продают не только данные, а ответственность: SLA, поддержку,
гарантированный доступ к судам и ФССП. Против этого «открытый код и честное
„не проверено“» — аргумент для инженера, а не для покупателя. Реальный рынок проекта —
AI-агентный слой, и ближайшая угроза там не Контур.Фокус, а **официальный MCP DaData**
с бесплатным тарифом и узнаваемым брендом.

## Где inn-check-ru сильнее (с границами)

1. **Открытая, воспроизводимая калибровка финансовых флагов.** 30 006 компаний, 3 210
   в детальном расчёте, 210 исходов (из них 52 — «производство прекращено»), с ДИ и
   данными. Граница: это оценка отдельных флагов на одной когорте, не точность
   светофора. Формулировка для публичных текстов — «нам не известна другая
   опубликованная воспроизводимая валидация в нише», а не «единственная».
2. **«Не проверено» ≠ «чисто» в коде.** С 1.12.2 это правда и для обязательных
   источников профиля: до него 🟢 выдавался при непроверенных судах (нашёл Codex).
3. **Методика, а не доступ к API:** 10 профилей цели сделки и нейтральный режим,
   финансы кодом с трассировкой к строке баланса, санкции РФМ/OFAC/ЕС (точное
   совпадение имени, без транслитерации), признаки дробления и «бумажного» НДС,
   ретро-вердикт (только по заранее сохранённым снимкам), досье.
4. **Без обязательного бэкенда и платного ключа:** базовые запросы ФНС идут от
   пользователя к госисточнику. Граница: граф связей требует ключ Checko; сам
   AI-клиент — облачная модель.

## Где слабее — приоритеты после ревью

1. ✅ **Сделано в 1.12.2:** 🟢 при непроверенных обязательных источниках; убраны
   неподтверждённые «~70% отсева» и «audit-it отстаёт на год».
2. **Полный сценарий в реальном агенте** (Cowork / Claude Code) с ручным добором судов
   и ФССП — `KNOWN_LIMITS` до сих пор фиксирует, что такого прогона не было.
3. **Сравнительный пилот:** один набор ИНН → inn-check-ru, mcp-fns-check, DaData MCP,
   Rusprofile. 10–20 ИНН годятся для поиска дефектов, но **не для оценки точности**:
   для неё нужны независимая разметка, одинаковые даты и отдельный учёт отказов от
   вердикта. Позиционирование — после результатов.
4. **Браузерный путь для судов, ФССП и ЕФРСБ как первоклассный сценарий:** агент
   открывает страницу, капчу решает пользователь. Плюс рецепт «своя нода в РФ».
5. **Ретро-валидация светофора и профилей**, по образцу калибровки.
6. **Системный риск:** бесплатные интерфейсы ФНС меняют формат и закрываются по
   гео — канарейки есть, но это риск всего каскада.

## Для кого inn-check-ru не подходит

- Бухгалтеру без AI-агента: 1С:Контрагент за 4 100 ₽/год или Rusprofile проще.
- Тем, кому нужны суды, ФССП и банкротства автоматически и мониторинг с
  уведомлениями: Фокус, СПАРК, API Checko.
- Работе вне РФ без своей российской ноды.
- Когда нужна юридически весомая справка: досье процедурное, практики по нему нет.
- Крупному бизнесу: отраслевые нормы собраны только по МСП.
