# Браузерное расширение inn-check-ru

Проверки и ручные результаты — через локальный движок (Python из этого репозитория), без
облака и без чтения страниц в фоне.

1. **Проверить ИНН с любой страницы.** Выделите ИНН в письме, счёте, карточке
   продавца → правая кнопка → «Проверить ИНН в inn-check-ru». Быстрая проверка
   по профилю из окна расширения; итог — на значке (`ok`, `~`, `!`, `?`) и в
   окне.
2. **Ручной блок ФССП и арбитражных судов.** На fssp.gov.ru или kad.arbitr.ru
   сами пройдите поиск (капчу — тоже сами), откройте окно расширения и впишите
   итог: число производств, крупные ли суммы, крупные ли иски. Блок ляжет в
   `~/inn-check-ru/<ИНН>/ручные/<блок>.json` по контракту
   `references/brauzer.md`. Кнопка «Блок и снимок в пакет» добавит снимок
   видимой части страницы в пакет доказательств (`evidence_pack.py`).
3. **Реестр залогов: вставьте текст страницы.** На reestr-zalogov.ru найдите
   залоги по ИНН залогодателя, выделите всю страницу результатов (Ctrl+A / ⌘A),
   скопируйте и вставьте в окно расширения. Число уведомлений, даты и
   залогодержателей посчитает код (`pledge_text.py`); имена физлиц и ИП не
   записываются. Несколько страниц результатов — итог «не проверено».

Итог «не проверено» (капча, вход, поиск не завершён) тоже записывается: он
перекрывает прежнее «проверено», а не пропадает.

## Установка (macOS, Linux, Windows)

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» →
   папка `extension/`. Скопируйте ID расширения (32 буквы).
2. Хост для связи с движком:

   ```bash
   python3 scripts/install_native_host.py --id <ID>
   # Brave, Chromium, Edge: --браузер brave | chromium | edge
   ```

   На Windows — `py scripts\install_native_host.py --id <ID>`: манифест и
   запускатель `.bat` лягут в `%LOCALAPPDATA%\inn-check-ru\native-host`, путь к
   манифесту — в ключ `HKCU\Software\<браузер>\NativeMessagingHosts\ru.inn_check_ru.host`.
   Путь к репозиторию и Python — без символов `" % ^ ! & < > |` и в кодировке
   консоли (кириллица годится): иначе установщик откажет, а не запишет битый `.bat`.

3. Перезапустите браузер.

Каталог данных — `~/inn-check-ru`; другой задаётся в
`~/.config/inn-check-ru/host.json`: `{"каталог": "~/Документы/проверки"}`.
Удалить хост: `python3 scripts/install_native_host.py --удалить`.

## Прикрепить результат к сохранённой проверке

Это маршрут неопубликованной версии 1.13.0 из текущих исходников. [Установите локальный workflow](../references/agent-workflow.md), затем настройте native host из той же версии. Расширение поддерживает ручной handoff, а не полный сбор/сравнение/replay. Реальное выполнение этого маршрута в пользовательском Chrome/native host ещё требует отдельной приёмки; протокольные и UI-тесты этого не заменяют. [Матрица](../references/capability-matrix.md).

В локальном CLI/MCP создайте сохранённую проверку и скопируйте её `run_id`.
На странице реестра откройте расширение, выберите «В сохранённую проверку по
run_id», вставьте UUID и нажмите «Загрузить выбранную проверку». Окно покажет
название, ИНН, профиль, ревизию, полный URL текущей вкладки и ожидаемый шаг.
ИНН формы заполните сами; затем явно подтвердите привязку к показанной проверке.
Последняя быстрая проверка автоматически не выбирается.

Выберите исход: «Проверка завершена», «Поиск не завершён» или «Отказываюсь от
ручной проверки». Для завершённого шага нужны поля результатов, параметры
поиска и отдельная отметка о просмотре всех страниц. Неполнота и отказ
сохраняются в новой ревизии, а пробел остаётся видимым. В режиме привязки поля
вводятся вручную; разбор текста залогов и снимки доступны в режиме отдельного блока.

Если проверка изменилась, окно перечитает именно выбранный `run_id` и покажет
актуальную ревизию. Для записи нужно снова нажать загрузку, сверить реквизиты и
подтвердить привязку. После потери ответа повтор того же запроса сохраняет
`operation_id` в течение браузерной сессии и не создаёт дубль. Завершение Chrome
очищает это состояние: сначала перечитайте run и проверьте сохранённый исход.

Хост принимает только `run_read {run_id}` и
`run_manual {run_id, expected_revision, operation_id, blocks}` с полем
`команда`; ответ — workflow envelope (`status`, `run_id`, `revision`, `data`,
`error`, `warnings`, `pending_actions`). Неизвестные поля отклоняются. URL,
ИНН, даты, срок действия, исход и ревизия проверяются повторно хостом/движком.
`root`, `path` и `executable` через страницу или сообщение не задаются.

Native-ответ ограничен **1 MiB JSON в UTF-8**, как требует Chrome. Маленький
workflow envelope сохраняет полные `data` и помечается
`native_projection: {version: 1, kind: "full", complete: true, omitted: [], truncated: []}`.
Если полный ответ с этой отметкой не помещается, хост возвращает **проекцию
для привязки**, а не полный отчёт: `kind: "binding", complete: false`.
`complete` описывает передачу полей ответа; полноту самой проверки по-прежнему
определяют `status` и сведения о доказательствах.
Правило одинаково для чтения, подтверждения ручной записи, повторного запроса
и ошибок; успешная запись не превращается в ошибку из-за размера отчёта.

Проекция сохраняет `status`, `run_id`, `revision`, `error` и прежние пути полей
окна: `data.fetch.инн`, `data.fetch.егрюл.название`, `data.metadata.profile`,
`data.metadata.manual_outcomes` для ФССП/судов/залогов и
`pending_actions[].{source_id,kind,reason_code}`. Также остаются
`data.fetch._decision.{decision_status,can_recommend}`,
`data.assessment.светофор`, `data.metadata.workflow_status` и краткие предупреждения.
`fin`, подробности источников/доказательств/решения, прочие исходы и дополнительные
поля шагов не передаются: категории перечислены в `native_projection.omitted`.
`full_payload_access: "CLI/MCP"` указывает, где прочитать полный материализованный результат.

Строки ограничены по символам: название и сообщение ошибки — 1024, профиль,
состояния и каждое поле шага — 128, исходы ручных блоков/код ошибки — 64,
сообщение предупреждения — 512, его код — 64, ИНН — 12. Усечённая строка
получает видимый суффикс `… [сокращено]`; перечень таких полей находится в
`native_projection.truncated`. Проекция включает первые 128 ожидаемых шагов
и 16 предупреждений в исходном порядке; полные количества указаны в
`pending_actions_total`/`warnings_total`, сокращение списков также отмечается
в `truncated`. Проверяется фактический размер сериализованного UTF-8 JSON,
включая экранирование и многобайтные символы. Защитный отказ
`error.code: "native_projection_too_large"` сохраняет workflow envelope и
идентификаторы уже совершённой операции.

Проекция строится только для ответа браузеру: сохранённые payload, их хеши,
старые ревизии, исходные ответы и доказательства не меняются. Полные данные
остаются доступны через CLI/MCP. Старые команды `проверить`, `ручной_блок` и
`доказательство` сохраняют прежний формат.

Хранилище сохранённых проверок задаёт среда процесса хоста
`INN_CHECK_RUNS_DIR`; по умолчанию это `~/.local/share/inn-check-ru/runs`.
CLI, MCP и native host должны использовать одно хранилище. Настройка
`host.json` «каталог» относится только к отдельным ручным блокам и пакетам.
Вне контекста расширения профиль использует временное хранилище в памяти;
это позволяет открывать окно для разработки, но не подключает Chrome/native host.

## Вклеить отдельные ручные блоки в проверку

```bash
python3 scripts/fetch_counterparty.py 7707083893 > fetch.json
python3 scripts/manual_block.py --вклеить fetch.json \
    ~/inn-check-ru/7707083893/ручные/суды.json \
    ~/inn-check-ru/7707083893/ручные/фссп.json -o fetch.ручные.json
python3 scripts/profiles.py --fetch fetch.ручные.json --профиль отсрочка
```

Снимок в пакет — только если пакет уже собран:
`python3 scripts/fetch_counterparty.py <ИНН> --пакет ~/inn-check-ru/<ИНН>/пакет`.

## Чего расширение не делает

- Не проходит капчи и не ставит галочки «Я не робот».
- Не ходит по реестрам в фоне и не читает страницы без вашего клика: права —
  `activeTab`, `contextMenus`, `nativeMessaging`, `storage`; доступа ко всем
  сайтам нет.
- Не читает DOM страницы: итог вводите вы; текст залогов разбирается только
  после явной вставки в режиме отдельного ручного блока.
- Снимок — только для юрлица (у ИП на странице ФССП его ФИО) и только с вашей
  отметкой «на экране нет ФИО физлиц». Не пишите ФИО в «что найдено».
- SHA-256 проверяет согласованность байтов, а не подлинность страницы, дату её публикации или полноту проверки. Без внешней доверенной метки владелец может пересчитать хеши; TSA — отдельный внешний запрос хеша и отдельная проверка подписи.
