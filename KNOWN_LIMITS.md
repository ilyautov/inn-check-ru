# KNOWN_LIMITS — честный список ограничений

Чего inn-check-ru **не умеет** или умеет с оговорками — на 22.09.2026 (v1.11.0). Не потому
что плохо сделано, а потому что честный «не проверено» полезнее правдоподобной
выдумки. Каждый пункт — со статусом: планируется / осознанно отложено /
требует РФ-IP.

## Источники

- **Реестр дисквалифицированных лиц: поиск по ИНН юрлица не работает.** Эндпоинт найден и верифицирован (`disqualified-proc.json`, без капчи, 8188 записей), но по ИНН организации он возвращает ноль даже там, где руководитель в реестре есть — поле не заполнено в индексе (проверено на пяти организациях 19.09.2026). Сверка идёт по ФИО руководителя из ЕГРЮЛ: совпадение по ФИО без даты рождения — повод проверить руками, а не идентификация лица. Требует перепроверки с РФ-IP.
- **Налоговая задолженность и недостоверность сведений отдельным реестром не берутся.** `service.nalog.ru/zd.do` выведен ФНС из эксплуатации («информация в Прозрачном бизнесе»), `invalid-addresses.do`/`mri.do`/`mn.do` редиректят на оплату или на pb, `uwsfind.do` жив, но требует капчу. Единственный путь — детальный эндпоинт «Прозрачного бизнеса», недоступный с не-РФ IP. Осознанно отложено.
- **Детальные риск-флаги «Прозрачного бизнеса» (долг, дисквалификация, массовость, ССЧ, спецрежим) — не собираются.** До 1.7.0 они парсились по угаданным именам полей и всегда были `null` при «ok». Теперь из поискового ответа берётся то, что он реально отдаёт (статус, ликвидация, недостоверность, ОКВЭД), а детали лежат за `company-proc.json`, который с не-РФ IP отвечает 500; подблок `риски.детали` — «не проверено», token сохранён. Требует РФ-IP или браузер.
- **Адрес из ЕГРЮЛ не отдаётся** поисковым `search-result` (только регион). Поле `адрес` — `null` с пометкой `адрес_источник`; адрес — из выписки/pb/агрегатора.
- **Перечень Росфинмониторинга берётся со страницы каталога, а не из выгрузки.** XML-URL отдаёт 404; перечень разбирается из HTML (23 803 записи, четыре раздела, верифицировано живым файлом 19.09.2026). Международная часть на эту дату пуста — разбор её разделов покрыт синтетической фикстурой, реальный формат записей неизвестен. Имена участников «объединений» стоят в родительном падеже, поэтому точная сверка по ним не сработает: нечёткий матч не вводим осознанно.
- **Суды (kad.arbitr) — ручной/браузерный слой.** Голый скрипт получает 451 за DDoS-Guard, API гео-блокируется. Осознанно отложено (нужен браузер или агрегатор).
- **ЕФРСБ скриптом — только юрлица и только по точному ИНН, с `Referer` сайта.** С 1.13 блок «банкротство» берётся из JSON, который дёргает сама страница bankrot.fedresurs.ru (`backend/cmpbankrupts`). Без заголовка `Referer` ЕФРСБ отвечает 403, с `Referer` главной страницы — JSON, от гео не зависит (проверено 26.09.2026). Это решение политики проекта, а не утверждение о законности: отправляем тот `Referer`, что отправляет страница сайта, и честный `User-Agent` со ссылкой на репозиторий, без маскировки под браузер (и без `X-Requested-With`); капчи, челленджи, ротация и повторы исключены — ровно один запрос, 401/403/429 и не-JSON дают «не проверено» с префиксом `антибот:`, `check_access.py` пишет такой отказ состоянием «антибот», а не «гео». `INN_CHECK_BEZ_REFERER=1` отключает запрос, источник становится браузерным, как до 1.13. Три границы. **ИП:** поиск физлиц (`prsnbankrupts`) с не-РФ IP отвечает 451, схему живьём не видели — для ИП «не покрыто», проверка вручную. **Что видно:** последнее дело и его стадию; сообщения, намерения кредиторов и история дел — нет (Федресурс — следующий шаг). **Стадии** известны по живым ответам (наблюдение, конкурсное производство, завершено, прекращено); незнакомая стадия — «не проверено: схема:» с кодом, а не молчаливое «нет». **Дисквалификация у банкротов:** у компании в конкурсном производстве и у ликвидированной поиск ЕГРЮЛ не отдаёт руководителя, поэтому сверка реестра дисквалифицированных по ФИО у них «не проверено» — ровно там, где она была бы интересна. Выдача ищется по точному ИНН: чужой ИНН в нечёткой выдаче не засчитывается, а если выдача длиннее страницы и точного ИНН на ней нет — «не проверено», а не «пусто».
- **ФССП — официальный API мёртв.** api-ip.fssp.gov.ru отключён с 10.03.2022 и не восстановлен: слой только браузерный (fssp.gov.ru) или агрегатор; для ИП — два поиска (по ИНН + по ФИО с датой рождения и регионом). Осознанно отложено.
- **НПД check-status — схема по официальному описанию, живой прогон ждёт РФ-IP.** С не-РФ IP сервис отвечает 406 (проверено 19.09.2026); состояние «не проверено», причина `гео:`. Требует РФ-IP.
- **npchk.nalog.ru (проверка НДС-контрагентов) — TLS не лечится корнем Минцифры.** Лист подписан GlobalSign, сервер не отдаёт промежуточный сертификат; probe показывает `tls`. Осознанно отложено.
- **Доступность снята с не-РФ IP.** `check_access.py` с текущей сети: гео — zakupki, fssp, kad.arbitr (нестабильно); tls — fedsfm/rosstat (лечится) и npchk (нет). С РФ-IP картина другая и её надо переснять — это отдельный прогон, результат ложится в тот же кэш (с 1.11.0 — помеченный отпечатком сети, так что прогон через ноду и прямой не путаются).
- **Прокси — только свой, и он видит, кого вы проверяете.** С 1.11.0 `--прокси` / `INN_CHECK_PROXY` / `HTTPS_PROXY` проводят и сбор, и probe через вашу ноду. Две оговорки, которые важнее удобства. **Первая:** узел видит АДРЕСА запросов — то есть список ИНН, которые вы проверяете. Содержимое он не читает и не подменяет, пока проверяется TLS (https идёт CONNECT-туннелем), но с `COUNTERPARTY_INSECURE=1` может и то, и другое. **Вторая:** общего прокси-пула у проекта нет и не будет (роадмап §11) — список проверяемых контрагентов это коммерческая тайна и картина ваших сделок до их заключения, а инструмент для проверки на доверие не может стоять на доверии к анонимному посреднику. Платные прокси-API — туда же (§8). Осознанно отложено навсегда.
- **`socks5://` не поддерживается.** Стандартная библиотека умеет только http/https-прокси, а зависимость ради socks проект не тащит — весь смысл stdlib-only в том, что скилл работает из коробки. Схема не игнорируется, а отвергается с текстом: молчаливое «пойдём напрямую» раскрыло бы IP там, где его прячут намеренно. Обходной путь: http-прокси на ноде или `ssh -L`. Осознанно отложено.
- **ЕРКНМ/РНП — сверка по кэшу работает (покрыта фикстурами), скачивание дампов не верифицировано.** Портал proverki.gov.ru с не-РФ IP открывается (200), но прямой URL дампа не подтверждён; zakupki.gov.ru — таймаут (проверено 19.09.2026); lookup схемно-агностичный, отдаёт сырой контекст записи. Требует РФ-IP.
- **Строки баланса из ГИР БО — подтверждены живым прогоном 19.09.2026** (ИНН 5036045205: 1200/1250/1300/1400/1500/1600/2110/2400, три года), фикстура в `eval/fixtures/net/`. Одна оговорка: `gainSum` из списка отчётностей равен строке 2110, но приоритет у детальной формы.

## Полнота данных

- **Полная выписка ЕГРЮЛ (история записей, учредители, залоги доли) не парсится.** Это PDF, а чистый stdlib PDF не читает — нужна внешняя зависимость. Осознанно отложено (принцип «только stdlib»). Базовый граф связей с v1.3.0 закрыт через checko API (`affiliates_graph.py`), но он требует бесплатный ключ `CHECKO_API_KEY`; поля checko API верифицированы по документации и фикстурам, живой прогон — после получения ключа.
- **Граф обходится лениво, и полным он не бывает по умолчанию.** С 1.10.0 обход останавливается на бюджете запросов (25), значимом статусе у связанной компании или пересечении с уже проверенными — ключ checko платный за объём. Это значит, что отсутствие признака дробления на таком графе НЕ означает его отсутствия в группе: неполнота помечается блоком `граф_неполон`, неразвёрнутые узлы перечисляются, но полный обход надо запросить руками (`--без-стопа --бюджет N --глубина N`). Осознанный размен: дешёвый ответ по умолчанию против полного по запросу.
- **Рёбра графа — один агрегатор (checko), tier ⚠️.** Каждое ребро помечено «требует пересечения»; фолбэк без ключа — ручной сбор браузером через `--offline-граф`. Офлайн-альтернатива (полный дамп ЕГРЮЛ) осознанно отложена в v2 — тяжёлый ETL оправдан, когда лимиты бесплатного ключа станут реальной проблемой.
- **ИП слепы финансово.** ИП не сдают публичную бухотчётность — fin_scoring для них честно отвечает «не проверено». Ограничение данных, не кода.
- **Суды не покрываются мониторингом снимков** — diff_counterparty сравнивает только то, что собирает скрипт. С формата 2 их агрегаты в отпечатке ЕСТЬ (для ретроспективы), но в дифф не идут намеренно: браузерный слой отвечает через раз, и мелькание «не проверено → 0 → не проверено» превратило бы дифф в шум, который перестают читать. Планируется (через браузерный слой). Банкротство юрлиц с 1.13 в дифф идёт: появление процедуры или смена стадии — 🔴. Снимки до 1.13 записали ЕФРСБ «не проверено» как предел инструмента; такое сравнение подавляется и сбоем прогона не считается (отпечаток хранит, какие источники в нём были «не покрыты»).
- **Дампы ФНС по ИНН ищутся, но индекс строится руками и покрывает не всех.** С 1.9.0 `opendata_index.py --построить` разворачивает выгрузки `snr`/`sshr2019`/`paytax` в отсортированный бинарный индекс, и `fetch_counterparty.py` отдаёт блок `дампы_фнс` (ССЧ, спецрежимы, уплаченные налоги), а признак `ндс_к_выручке` в `paper_vat.py` перестал быть вечным «не проверено». Две оговорки, которые никуда не делись. **Первая:** индекс не собирается сам — нужны скачанные дампы (сотни мегабайт) и ручной прогон; без индекса состояние `не проверено` с причиной `кэш:`, и это не деградирует в ноль. **Вторая:** записи есть не на всех — `snr` перечисляет только применяющих спецрежимы (52% выборки), `sshr` покрывает 99%, `paytax` 100% среди сдающих отчётность, но отсутствие проверено живьём: Сбербанка (7707083893) нет ни в `sshr2019`, ни в `paytax` — grep по самим архивам, не по индексу. Поэтому «нет записи» возвращается как «пусто» с оговоркой про охват, а не как «нет сотрудников». Сведения ДАТИРОВАНЫ выгрузкой: дата едет в каждом ответе, и сравнение НДС одного года с выручкой другого скрипт делать отказывается — признак вернётся «не проверено» с названными годами. ИП (12 цифр) вне охвата этих датасетов вовсе, и поиск по ним отказывается с причиной `охват:`. Недоимка (`debtam`) квартальная: сигнал `налоговая_задолженность` из дампа отражает долг на дату состояния (выгрузка 25.09.2026 — на 01.09.2026) без учёта погашения после неё; отсутствие записи сигнал не снимает и «долга нет» не означает. `taxoffence` — не «все штрафы»: только решения, вступившие в силу за один год, со штрафом, не уплаченным к 1 октября следующего; с недоимкой не складывается. Пакет доказательств хранит ответы как есть — в ответах ЕГРЮЛ есть ФИО руководителей (публичные сведения реестра), поэтому пакет — документ с ПДн, а не обезличенный отчёт. Реестр дисквалифицированных дампом (`registerdisqualified`) сознательно не подключён: ИНН организации в нём — место работы в момент нарушения, а не текущее, и совпадение по ИНН контрагента дало бы ложный стоп-сигнал.
- **Отраслевые нормы для «среднего» и «крупного» — не нормы отрасли.** ОКВЭД в открытых данных ФНС есть только в реестре МСП, поэтому группы собраны по субъектам МСП: настоящего крупного бизнеса в них нет. Скрипт это не скрывает — сравнение большой компании возвращается с `предупреждение` вместо перцентиля. Ограничение данных, не кода.
- **Нормы стоят на выгрузках дампов, а не на живом запросе.** Таблица `data/benchmarks_ru.json` (5480 групп) пересобирается вручную `opendata_refresh.py --refresh` + `benchmarks.py --построить`; между пересборками она стареет вместе с выгрузкой ФНС. Год отчётности, по которому построена группа, едет в выводе — сравнение выручки 2025 года с нормой 2023-го видно глазом, а не прячется. Автообновления нет осознанно: дампы весят сотни мегабайт.
- **Признаки «бумажного» НДС считаются по тому, что открыто, а ключевое закрыто.** Разрывы АСК НДС-2, книги покупок и продаж, движение по счетам — налоговая тайна, и в открытых данных их нет. `paper_vat.py` перечисляет это отдельным блоком «чего не видно» и не выносит налоговых заключений: по п. 3 ст. 54.1 НК РФ нарушение контрагента само по себе не основание снять вычет. Ограничение закона, не кода.

## Методология

- **Social preview в Settings — ручной шаг.** GitHub не даёт API для загрузки картинки (проверено 19.09.2026): Settings → Social preview → `assets/social-preview.png`. Генератор и гейт свежести — в CI, загрузка — руками один раз.
- **PyPI: `inn-check-ru` опубликован с 1.11.0, `inn-check-ru-mcp` — с 1.11.1.** Публикация идёт сама по пушу тега (Trusted Publishing). Перед заливкой workflow ставит колесо движка в чистый venv и запускает сервер той же командой, которую соберёт клиент реестра (`eval/mcp_handshake.py`).
- **MCP Registry: публикация — автоматически по тегу, после PyPI (`publish-registry.yml`, вход GitHub OIDC).** Две причины отказа реестра закрыты гейтом: исполняемый файл с именем пакета должен запускать сервер, в README пакета должна стоять строка `mcp-name:`. До 1.11.1 не выполнялось ни то, ни другое. Реестр принимает версию, только когда PyPI уже отдаёт оба пакета — workflow ждёт до 5 минут.
- **MCP-сервер — живой stdio-хендшейк есть, сессии с клиентом-агентом нет.** С 19.09.2026 дымовой тест поднимает сервер отдельным процессом и гоняет initialize / tools/list / tools/call по транспорту (14 инструментов, движок достижим, `serverInfo.version` равен версии релиза, а не версии SDK). Чего ещё не было: прогона внутри Claude Code или Cursor как инструмента агента. Планируется (живой клиент).
- **`.mcp.json` плагина был сломан и починен 19.09.2026.** Строка запуска звала `python3 mcp/server.py`, а системный `python3` пакета `mcp` не содержит — клиент получал «Connection closed». Теперь запуск идёт через `uv run --no-project --with "mcp>=1.30,<2"`, и это проверено живым хендшейком. Два подвода, из-за которых поломка жила незамеченной, записаны в `mcp/README.md`: каталог `mcp/` в репозитории теневает пакет SDK при любом `import mcp` из корня, а `uvx --from <локальный путь>` кэширует сборку и поднимает устаревший код (`--refresh` кэш не сбрасывает). Авто-подхват именно плагином по-прежнему не проверен.
- **Профили цели — веса заданы экспертно, не откалиброваны.** Одиннадцать профилей в `data/profiles_ru.json` (deal-killer'ы, `severity_override`) — из методик ФНС и практики, без ретроспективной выборки. Резолвер только поднимает тревожность; спор о весе — issue `threshold`.
- **Финансовые пороги проверены на одной когорте, и флаги — сигнал, а не прогноз.** С 24.09.2026 автономия < 0,1, ликвидность < 1 и падение выручки > 50% откалиброваны на 30 006 компаниях с отчётностью за 2021 год против банкротств 2022–2024 (ЕФРСБ): пороги оставлены, лучших по правилу проекта в сетке нет. Флаг поднимает частоту банкротства в 1,3–3,6 раза, но из флагнутых банкротятся 1–5%. «ЧА отрицательные два года» и падение выручки на всей когорте статистически не значимы (ДИ лифта включает 1), значимы у операционных компаний; красный уровень ЧА держится на ст. 30 ФЗ-14, а не на прогнозе. Ликвидность считается только у трети компаний (упрощённый баланс). Не откалиброваны: «ЧА ниже уставного капитала», транзитный профиль (рост 300%), чеклист однодневки. Одна когорта в период санкционного шока — перенос на другие годы не проверен. Подробно: [references/kalibrovka.md](references/kalibrovka.md).
- **Пакет доказательств доказывает неизменность, а не подлинность.** `--пакет` хранит байты ответов источников с SHA-256, но сами источники их не подписывают: пакет (со штампом) показывает, что после сбора ничего не меняли, а не что сервер ФНС отдал именно эти байты. Без штампа хеши доказывают лишь согласованность файлов — владелец пакета мог пересчитать их все. Штамп RFC 3161 публичного TSA (freetsa.org, DigiCert) — не квалифицированная метка времени по 63-ФЗ; подпись штампа модуль не проверяет (нужна криптография вне stdlib) — это делает `openssl ts -verify`. Запросы, упавшие по таймауту или DNS, байт не дают: они видны в `_доступность` fetch.json, а не в `raw/`. Практики по таким пакетам в налоговых спорах нет. Тройка критериев в досье — стандарт судебной практики, изложенный в письме ФНС БВ-4-7/3060@; сопоставление с источниками — подсказка инструмента, а не текст письма.
- **Досье осмотрительности — отчёт инструмента, а не документ госоргана.** `dossier.py` фиксирует, что было видно в открытых источниках на дату и время проверки, с хешем исходного JSON. Юридическая ценность процедурная и появляется, только если досье составлено **до** сделки; судебной практики именно по такому документу нет. Источник, о котором во входном JSON нет сведений, помечается «сведений во входе нет» — это третье состояние рядом с «ответил» и «не проверено», и в 🟢 оно не превращается.
- **Вынесенные разделы скилла агент читает сам — автозагрузки нет.** SKILL.md разрезан (84 КБ → 53 КБ), справочное лежит в `references/` и открывается по поводу, названному в таблице в начале файла. В Claude Code и любом агенте с чтением файлов это работает; в среде, где файловых инструментов нет (например, чистый MCP-клиент без доступа к диску), вынесенные разделы недоступны — тогда ветка ИП, мониторинг и батч останутся за кадром. Гейт `run_skill_gate.py` следит за ссылками, сиротами и наличием файлов в релизном архиве, но заставить хост открыть файл он не может. Осознанный размен: файл на 84 КБ вытеснял из контекста саму задачу.
- **Извлечение ИНН ловит число, а не контрагента.** `extract_inn.py` режет мусор контрольным числом ФНС, но ИНН вашей собственной компании, ИНН банка в реквизитах и ИНН из подписи письма для него такие же ИНН. Роль («кто поставщик») из текста не выводится — осознанно: ошибка в роли дороже лишней проверки. Вложения `.eml` (PDF, xlsx) не разбираются, а перечисляются пометкой.
- **Сверка по имени — только точное совпадение.** Нечёткий матч и транслитератор осознанно не встроены: однофамильцы дают ложные срабатывания, опасные в санкционном контуре. Любое совпадение по имени требует ручной сверки по дате рождения. Осознанно отложено.
- **Снимки мониторинга — локальные, планировщик не ставится сам.** `watchlist.py --установить-расписание` печатает готовые строки crontab и launchd plist, но правку расписания оставляет пользователю: менять системные задания без спроса инструмент не должен. Облачного мониторинга нет — осознанно.
- **Снимок хранится отпечатком, а не полным слепком; ретроспектива считается только по тому, что в нём есть.** В отпечатке поля диффа, состояния источников, SHA-256 остального и (с формата 2) блок «вердикт» — агрегаты deal-killer-источников, без которых светофор на дату не считается. `retro_verdict.py` берёт последний снимок НЕ ПОЗЖЕ запрошенной даты, из сети ничего не добирает и не превращает «значения не сохранены» в «признака не было»: такие сигналы остаются «не проверено», и 🟢 по ним не выдаётся. Отсюда два живых ограничения. **Первое:** снимки формата 1 (до 1.10.0) агрегатов не хранят — ретроспектива по ним назовёт источники без значений и светофора не выдаст. **Второе:** ретроспектива есть только там, где снимки делались ЗАРАНЕЕ и полным режимом; прошлое не переспрашивается, и «добрать по каскаду» задним числом невозможно. Снимок урезанного профиля или quick-режима помечается в выводе отдельным предупреждением.
- **Дефект среды, не кода:** в Python 3.14.6 из Homebrew не грузится `pyexpat`, поэтому разбор EU-перечня там честно деградирует в «не проверено»; под системным Python и в venv он работает.
