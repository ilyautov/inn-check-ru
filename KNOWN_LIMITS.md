# KNOWN_LIMITS — честный список ограничений

Чего inn-check-ru **не умеет** или умеет с оговорками — на 19.09.2026. Не потому
что плохо сделано, а потому что честный «не проверено» полезнее правдоподобной
выдумки. Каждый пункт — со статусом: планируется / осознанно отложено /
требует РФ-IP.

## Источники

- **Спецреестры ФНС (service.nalog.ru: дисквалификация, задолженность, недостоверность) — не верифицированы.** POST не возвращает token с не-РФ IP; форма запроса требует живой разведки. Требует прогона с РФ-IP.
- **Схема XML перечня Росфинмониторинга не верифицирована на живом файле.** Парсер написан defensive по историческому формату и проверен на синтетике; после первого реального `--refresh` схему полей стоит сверить. Требует РФ-IP.
- **Суды (kad.arbitr) и банкротства (ЕФРСБ) — ручной/браузерный слой.** Голый скрипт получает 451 за DDoS-Guard, API гео-блокируется. Осознанно отложено (нужен браузер или агрегатор).
- **ФССП — официальный API мёртв.** api-ip.fssp.gov.ru отключён с 10.03.2022 и не восстановлен: слой только браузерный (fssp.gov.ru) или агрегатор; для ИП — два поиска (по ИНН + по ФИО с датой рождения и регионом). Осознанно отложено.
- **НПД check-status — схема по официальному описанию, живой прогон ждёт РФ-IP.** С не-РФ IP сервис отвечает 406/403 (проверено 19.09.2026); парсер покрыт фикстурой. Требует РФ-IP.
- **ЕРКНМ/РНП — сверка по кэшу работает (покрыта фикстурами), скачивание дампов ждёт РФ-IP.** proverki.gov.ru отдаёт 400, zakupki.gov.ru — таймаут с не-РФ IP (проверено 19.09.2026); lookup схемно-агностичный, отдаёт сырой контекст записи. Требует РФ-IP.
- **Строки баланса 1300/1200/1250/1400/1500 из ГИР БО — по аналогии с подтверждённой current1600.** Нужен прогон на ИНН с реальной отчётностью. Требует РФ-IP.

## Полнота данных

- **Полная выписка ЕГРЮЛ (история записей, учредители, залоги доли) не парсится.** Это PDF, а чистый stdlib PDF не читает — нужна внешняя зависимость. Осознанно отложено (принцип «только stdlib»). Базовый граф связей с v1.3.0 закрыт через checko API (`affiliates_graph.py`), но он требует бесплатный ключ `CHECKO_API_KEY`; поля checko API верифицированы по документации и фикстурам, живой прогон — после получения ключа.
- **Рёбра графа — один агрегатор (checko), tier ⚠️.** Каждое ребро помечено «требует пересечения»; фолбэк без ключа — ручной сбор браузером через `--offline-граф`. Офлайн-альтернатива (полный дамп ЕГРЮЛ) осознанно отложена в v2 — тяжёлый ETL оправдан, когда лимиты бесплатного ключа станут реальной проблемой.
- **ИП слепы финансово.** ИП не сдают публичную бухотчётность — fin_scoring для них честно отвечает «не проверено». Ограничение данных, не кода.
- **Суды и банкротства не покрываются мониторингом снимков** — diff_counterparty сравнивает только то, что собирает скрипт. Планируется (через браузерный слой).

## Методология

- **Пороги эвристические, не откалиброваны на выборке.** Автономия 0.1, ликвидность 1, падение выручки 50%, рост 300% — разумные стартовые значения из методичек ФНС/банковского анализа, но статистической калибровки по базе контрагентов не было. Планируется (нужна размеченная выборка).
- **Сверка по имени — только точное совпадение.** Нечёткий матч и транслитератор осознанно не встроены: однофамильцы дают ложные срабатывания, опасные в санкционном контуре. Любое совпадение по имени требует ручной сверки по дате рождения. Осознанно отложено.
- **Снимки мониторинга — локальные, без облака и расписания.** Ритм «снимок перед отгрузкой» — на дисциплине пользователя или кроне агента; встроенного планировщика нет. Осознанно отложено.
