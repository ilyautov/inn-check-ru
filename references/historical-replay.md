# Исторический replay

Читать перед восстановлением исходного исторического решения или явным пересчётом по текущим правилам.

`historical_replay.replay(run_id, *, mode, cutoff, root=None)` читает только локальные зафиксированные ревизии. Сеть, новый сбор, provider fallback, создание каталогов и запись артефактов здесь отсутствуют. `root` — доверенная настройка хоста, по умолчанию `INN_CHECK_RUNS_DIR` / каталог run store. Значение из сохранённых данных не используется как путь.

```sh
python3 scripts/workflow_cli.py run replay UUID --mode original --cutoff 2022-05-01T09:00:00Z
python3 scripts/workflow_cli.py run replay UUID --mode current_rules --cutoff 2022-05-01T12:00:00+03:00
```

CLI возвращает один стандартный workflow envelope, внутри `data` которого лежит результат replay. API возвращает непосредственно результат replay. Cutoff требует полную дату, время с секундами и часовой пояс; нормализуется в UTC. Дата без времени, время без пояса и неверные смещения отвергаются. Отсечение включительное. Если HEAD создан позднее cutoff, читается предшествующая зафиксированная ревизия. Если подходящей ревизии нет, `ReplayError.code == "no_revision_at_cutoff"`. Orphan-файлы вне цепочки HEAD не участвуют; целостность цепочки проверяет run store.

## Два режима

`original` возвращает `data == record["payload"]`: полный сохранённый объект `{fetch, fin, assessment, metadata}`, а не только цвет или assessment. `manifest == record["manifest"]`. Скоринг и разрешение сигналов повторно не вызываются; `original_rules_version` и `applied_rules_version` равны сохранённому хешу правил (или null, если у legacy-ревизии он отсутствует). Даже если сохранённый результат включает недатированный факт, исторический payload не переписывается. Ограничение явно находится в `exclusions` и `point_in_time_status`. Такой результат нельзя объявлять подтверждённым состоянием на дату.

`current_rules` формирует новый вход из датированных сохранённых листьев, вызывает существующий `evidence_contract.evaluate` с часами cutoff и возвращает новый материализованный результат. Неподтверждённые по времени значения и прежние производные показатели в скоринг не поступают. Производные считаются заново из допущенных листьев. Данные и файлы исходной ревизии остаются неизменными. Неизвестные листы не становятся положительными фактами при повторной адаптации legacy JSON.

Новый `artifact_manifest` содержит исходный run/revision, хеш исходного manifest, исходного payload, отфильтрованного входа и нового результата, исходную и применённую версии правил, cutoff, исключения. `original_historical_outcome` всегда `false`: это результат нынешних правил на старых доступных данных. Часы cutoff задают возраст фактов; они не утверждают, что нынешние правила существовали тогда. `manifest` в обоих режимах остаётся исходным manifest. Новое значение rules hash находится отдельно в `applied_rules_version`.

Артефакт возвращается в памяти. Его сохранение/экспорт должно быть отдельной явной операцией с экспортной политикой захваченного провайдера. Локальное чтение и CLI replay не являются лицензированным внешним экспортом. Захваченный `_provider_policy` и metadata сохраняются; текущая конфигурация провайдера не читается. Каноническая редакция секретов применяется хранилищем, а также новым результатом пересчёта. Raw refs сохраняются как происхождение; replay не обещает восстановить утраченные raw bytes.

## Когда факт допустим на дату

Отчётный год, период действия и `actualBfoDate` сами по себе не доказывают доступность публикации. Факт допускается, если `first_observed_at <= cutoff` либо `published_at <= cutoff` имеет явное подтверждение семантики публичной доступности. Retrieval сам по себе не заменяет ни одну из этих дат.

Первое наблюдение — сохранённое наблюдение системы, не заявление об исторической публикации. Для ветки публикации сохраните в materialized metadata дополнительный реестр, связанный с конкретным claim id и его raw hash:

```json
{
  "publication_semantics": {
    "sha256:CLAIM_ID": {
      "confirmed": true,
      "meaning": "public_availability",
      "reference": "ссылка на проверенный паспорт источника и смысл поля"
    }
  }
}
```

Это утверждение доверенного адаптера, которое нужно подтвердить документацией источника; replay его самостоятельно в сети не проверяет. Одной строки `published_at` без этой записи недостаточно; для этой ветки также требуется сохранённый raw ref со статусом `available`. У ручных/legacy источников без дат редакции — `edition_availability_unknown`. Позднее наблюдение — `observed_after_cutoff`; поздняя подтверждённая публикация — `publication_after_cutoff`.

При пересчёте replay явно передаёт этот реестр в `evaluate(..., publication_semantics=...)`. Оценщик проверяет основание для конкретного claim, включая доступный raw, дату и ссылку на семантику. Подтверждённая публикация снимает только запрет позднего retrieval/первого наблюдения; реальные timestamps остаются прежними, срок актуальности, конфликт и полнота источника продолжают проверяться. Обычный вызов `evaluate` без этого аргумента не наследует разрешение из предыдущего, вложенного или параллельного вызова.

Сохранённые служебные поля источника (`статус`, `дата_проверки`, `url`, `ввод`) нужны для повторной проверки ручных/браузерных источников. Replay переносит их из выбранной ревизии только если **все исходные ненулевые недеривативные claims источника**, включая впоследствии исключённые, имеют доступный raw и фактическое первое наблюдение не позднее cutoff. Поле, само являющееся tracked claim, по этому пути не копируется. Подтверждённая ранняя публикация при позднем наблюдении не разрешает перенос позднего контекста полноты поиска: рекомендация остаётся ограниченной через `missing_evidence` / `source_unavailable`. Частичный поиск и пропущенные факты сохраняют unknown. `point_in_time_status` по-прежнему описывает даты листьев, а не полноту такого контекста.

`point_in_time_status` описывает датируемость наблюдаемых листьев, а не полноту проверки компании или вероятность ошибки:

- `verified`: все ненулевые недеривативные листы имеют допустимое основание по времени;
- `partial`: допустима только часть таких листьев;
- `unverified`: нет допустимых листьев либо отсутствует/некорректен evidence contract.

Неизвестные отсутствующие поля не превращаются в доказанное отсутствие риска. Статусы знаний, полнота и допустимость рекомендации остаются в `_evidence` / `_decision` нового или сохранённого результата.

## Legacy retro и границы проверки

`retro_verdict.py` сохраняет старый CLI и старые поля результата. Успешный результат дополнительно помечен `replay_mode: current_rules`, `original_historical_outcome: false`; оговорка поясняет пересчёт. Сохранённого исходного решения старый snapshot не доказывает. Для неизменного исторического решения используйте `original` на materialized run.

`eval/run_historical_replay_eval.py` проверяет синтетическую отчётность 2021 года с наблюдением после cutoff 2022 года, позднюю корректировку отдельной ревизией, побайтовую неизменность исходного payload/manifest, временную замену ресурса порогов, строгий cutoff, CLI, захваченную policy, отсутствие записей и сетевых соединений в replay через audit hook. Эти проверки подтверждают механизм. Реальных датированных пар редакций: **0**. Статус: **awaiting_external_evidence**. Реальные публикации, права на материалы и архивная доступность не выдумываются.
