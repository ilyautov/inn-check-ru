# Браузерный шаг: суды, ФССП, банкротство ИП, карты

**Расширяет «ПРАВИЛО ПРО КАПЧУ» SKILL.md. Читать перед тем, как открывать
kad.arbitr, fssp.gov.ru, bankrot.fedresurs.ru или карты в браузере пользователя.**

Скриптом эти источники не берутся: kad.arbitr за DDoS-Guard (голый запрос = 451),
официальный API ФССП отключён с 10.03.2022, поиск ИП в ЕФРСБ с не-РФ IP — 451,
HTML fedresurs.ru закрыт JS-челленджем. Снимок помечает их `требует: браузер`
или «не покрыто:», и мониторинг не считает их пропажу изменением.

## Согласие и капча

1. **Сначала спросить.** Браузер — это вкладки пользователя и его IP. Без явного
   «да» в чате браузер не открываем; «нет» — блок остаётся «не проверено» с
   пометкой «проверьте вручную: <URL>».
2. **Капчу решает пользователь, агент её не трогает.** Ни распознавания, ни
   сервисов-решателей, ни кликов по чекбоксу «я не робот», ни обхода челленджа.
   Увидел капчу — пишешь «на странице капча, решите её и скажите „готово“»
   и ждёшь. Не решил — «не проверено: капча:».
3. **Паролей и кодов не вводим.** Страница просит вход — это конец шага, а не
   повод логиниться.
4. **Ничего не выдумываем.** Не удалось дочитать выдачу (пагинация, таймаут,
   обрыв) — это «не проверено» или «проверено частично» с указанием, что
   просмотрено; не «чисто».

## Что искать

| Источник | Поиск | Что записать |
|---|---|---|
| kad.arbitr.ru | по ИНН в поле «Участник дела»; отдельно роли истец / ответчик | число дел ответчиком за 3 года, сумма, крупные (> 10% выручки) |
| fssp.gov.ru | юрлицо: по наименованию + регион. ИП: **два** поиска — как юрлицо и как физлицо (ФИО + дата рождения + регион) | число ИП, сумма остатка, есть ли по налогам |
| bankrot.fedresurs.ru | ИП и то, что скрипт дал «антибот:» / «не покрыто:» | номер дела, стадия, дата |
| fedresurs.ru | реорганизация, уменьшение УК, залог доли (скриптом не подключены) | тип сообщения, дата, номер |

## Контракт ручного блока

Данные из браузера кладутся в fetch-JSON блоком источника. Код
(`profiles._состояние_блока`) принимает ручной блок (`ввод: "браузер"`,
браузерный источник — суды, ФССП — или свой `статус: "проверено"` поверх
молчавшего скрипта) как проверенный, **только если** он заявлен проверенным
(`статус: "проверено"` или `_доступность.<id>.состояние = "ok"`) и есть
`дата_проверки` (ГГГГ-ММ-ДД) и `url` (http/https) — в самом блоке или в
`_доступность.<id>`. Иначе блок остаётся «не проверено» с причиной «ручной
блок без …», и 🟢 не выдаётся. Своё `статус: "не проверено: …"` у блока
побеждает всегда, даже с датой и URL.

```json
"суды": {
  "статус": "проверено",
  "ввод": "браузер",
  "дата_проверки": "2026-09-26",
  "url": "https://kad.arbitr.ru/",
  "параметры_поиска": "ИНН 7707083893, участник дела, 3 года",
  "просмотрено": "2 страницы, 37 дел",
  "найдено": "ответчик в 5 делах на 1,2 млн ₽",
  "проверил": "пользователь",
  "ответчик_дел": 5, "ответчик_сумма": 1200000, "ответчик_крупные": false
}
```

`параметры_поиска`, `просмотрено`, `найдено`, `проверил` код не требует, но без
них проверку нельзя повторить, и в пакете доказательств она весит меньше.

## В пакет доказательств

Сохранённую страницу (PDF, HTML, скриншот) пользователь добавляет в пакет:

```
python3 scripts/evidence_pack.py --добавить <каталог> kad.pdf --источник суды \
    --url https://kad.arbitr.ru/ --дата 2026-09-26 \
    --параметры "ИНН 7707083893" --просмотрено 37 --найдено "5 дел ответчиком"
```

`--дата` обязательна: день проверки знает только пользователь. Файл ложится в
`manual/NNN_суды.pdf` с описью `NNN_суды.опись.json`, пакет получает новую
версию манифеста (`manifest.N.json`) со ссылкой на предыдущую; если у прошлой
версии был штамп времени — ставится и у новой (`--без-штампа` отключает).
Прежние версии и их штампы не переписываются никогда. `--проверить` сверяет
всю цепочку: полноту истории, накопительный состав, описи. Штамп версии
доказывает, что вложение существовало не позже его времени, — но не то, что
страница выглядела именно так; версия без штампа не доказывает и времени.

## Карты и отзывы

Только по просьбе пользователя и только вручную в его браузере.

- **Совпадение адреса обязательно.** Карточка на картах засчитывается, если
  адрес совпадает с юридическим или фактическим адресом из ЕГРЮЛ/договора;
  одно совпадение названия — не та же компания.
- **Только агрегаты:** есть ли карточка, рейтинг, число отзывов, дата
  последнего отзыва, доля жалоб на невыполнение обязательств (оценка «на глаз»
  с пометкой, сколько отзывов просмотрено).
- **Без имён авторов**, без цитат, позволяющих узнать автора, без скриншотов,
  где видны авторы. В пакет доказательств такие скриншоты не кладём.
- **Не в светофоре.** Отзывы — контекст для разговора с контрагентом, не
  сигнал профиля: рейтинг легко накрутить и легко утопить.
