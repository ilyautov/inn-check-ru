# Граф связей и признаки дробления

**Расширяет SKILL.md. Читать, когда проверка дошла до связей:** подозрение на группу компаний, вопрос «кто за этим стоит», признаки дробления бизнеса, оценка доли в компании. Для быстрой проверки контрагента граф не нужен.

## Аффилированность и признаки дробления

Слой полного досье (quick-scan без ключа не ломается). Два скрипта:

1. **Граф связей** — `python3 scripts/affiliates_graph.py <ИНН>` (нужен бесплатный ключ checko, env `CHECKO_API_KEY`; без ключа — честное «не проверено», exit 0). Целевая компания → директор и учредители → их компании (checko `СвязРуковод`/`СвязУчред`) + соседи по адресу (`МассАдрес`) + правопреемство. BFS на глубину 2, лимит 100 узлов с пометкой «усечено». Выход: узлы (название, ИНН, статус, тип связи) + рёбра `{от, до, тип, через}`.
2. **Чеклист дробления кодом** — `affiliates_graph.py <ИНН> | python3 scripts/droblenie_check.py --stdin`. Считает по графу и выручке ГИР БО: общий директор; общий учредитель; единый адрес; идентичный основной ОКВЭД; все на УСН; **каждая компания под порогом освобождения от НДС, а группа в сумме над ним**; группа над лимитом УСН; численность ~0 при выручке. Каждый признак — факт с источником. Severity: 3+ → 🟡, 5+ → 🔴 (синхронно с чеклистом однодневки).

**Пороги — из канона, не из кода:** `data/canon_ru.json` — каждое число с источником и датой проверки: освобождение от НДС на УСН, лимит УСН и переходный лимит. Конкретные значения здесь не дублируются намеренно — проза устаревает молча, а канон правится в одном месте и несёт норму с датой (`python3 -c "import json;print(json.load(open('data/canon_ru.json'))['пороги'])"`). Канон отсутствует/битый → блок выручки честно «не проверено».

**Формулировочная дисциплина (обязательно).** Суды прямо говорят: аффилированность сама по себе не доказывает дробление. Вывод скоринга — всегда «N признаков, совпадающих с типовыми доводами ФНС по спорам о дроблении (письмо БВ-4-7/8051@ от 16.07.2024)» — никогда «это дробление». Доказывание у ФНС — совокупность признаков + вторичный контур (IP клиент-банка, финпотоки, единая 1С), который открытыми данными не проверяется; наш светофор — раннее предупреждение, не заключение.

### Транспорт рёбер и доверие

Принцип «одиночному источнику не верим» действует и на граф: каждое ребро и каждый связанный узел помечаются `tier: "⚠️ один источник (checko API), требует пересечения"` (целевая карточка — `✅ ЕГРЮЛ`), а в корне вывода — оговорка о необходимости пересечения. Каскад транспортов рёбер:

1. **checko API** (ключ `CHECKO_API_KEY`) — быстрый путь; ключ — ускорение, а не требование.
2. **Браузерный фолбэк** — те же карточки checko/rusprofile/СБИС через Claude-in-Chrome: собранные вручную связи подаются в `python3 scripts/affiliates_graph.py --offline-граф файл.json` (формат узлы/рёбра тот же), сеть скриптом не дёргается, `droblenie_check.py` работает поверх.
3. **Перед решением по группе** ключевые рёбра пересекаются вторым источником (ЕГРЮЛ-выписка, rusprofile, СБИС) — ⚠️ превращается в ✅ только так.

Стратегическая пометка: офлайн-граф из полного дампа ЕГРЮЛ (учредители и история записей в открытом дампе ФНС) — направление v2, осознанно отложено: тяжёлый ETL оправдан, когда лимиты бесплатного ключа станут реальной проблемой пользователей.
