# Политика провайдеров v1

Читать перед настройкой ключей, платного fallback, бюджета и экспортных ограничений провайдеров.

Политика задаётся владельцем хоста: `INN_CHECK_PROVIDER_POLICY=/absolute/path/policy.json`.
Путь принимается только из окружения процесса, должен быть абсолютным; файл ограничен
64 KiB. В CLI/MCP/странице нет аргумента для подмены этого пути, исполнителя или URL.
Отсутствие настройки сохраняет прежний выбор одного ключа: Checko, иначе DaData.
Автоматического fallback без политики нет.

Пример локального файла (условные единицы оператора, **не цена поставщика**):

```json
{
  "schema_version": 1,
  "total_cost_units": 4,
  "providers": [
    {
      "id": "checko",
      "enabled": true,
      "allowed_fields": ["недостоверность_сведений"],
      "export_fields": [],
      "request_limit": 3,
      "request_cost_units": 1,
      "fallback_on": ["quota_exhausted", "unavailable"],
      "transient_retries": 0
    },
    {
      "id": "dadata",
      "enabled": true,
      "allowed_fields": ["недостоверность_сведений"],
      "export_fields": [],
      "request_limit": 1,
      "request_cost_units": 1,
      "fallback_on": []
    }
  ]
}
```

Ключи по-прежнему передаются через `CHECKO_API_KEY` и `DADATA_API_KEY`.
Политика не содержит секретов. Неизвестные ключи/версии/провайдеры/поля,
повторяющиеся провайдеры, отрицательные и нецелые бюджеты, булевы числа,
экспорт вне `allowed_fields` отклоняются. JSON Schema поставляется в
`data/provider_policy.schema.json`; дополнительные межполевые ограничения
проверяет stdlib-функция `validate_policy`.

## Поля и фактические возможности

Checko: `name`, `address`, `недостоверность_сведений`, `недостоверность`,
`дисквалификация_руководителя`, `дисквалификация`, `graph`.
DaData: `name`, `address`, `недостоверность_сведений`.
Отсутствие поля в ответе не превращается в отрицательный результат.
Используются существующие парсеры Checko/DaData; имя/адрес извлекаются из
соответствующих полей карточки. Исходные API возвращают целую карточку:
allowlist ограничивает возвращаемые нормализованные поля, а не состав
ответа провайдера по сети. Полный ответ может сохраняться только во
внутреннем локальном архиве запуска.

`graph` означает карточку Checko для существующего графового парсера. У DaData
в этом адаптере нет графовых данных: fallback графа запрещён. При отсутствии
разрешений/бюджета сеть не вызывается. Граф CLI использует один ledger на весь
обход. Предел 25 включает повторы; меньший `--бюджет` также ограничивает
фактические обращения. Общий дедлайн обычного fetch остаётся 120 секунд
по умолчанию и ограничивает транспорт политики.

## Бюджет и fallback

Публичные контракты:

```python
validate_policy(policy: dict) -> list[dict]
fetch_with_policy(inn: str, fields: list[str], policy: dict, *, request, ledger: dict) -> dict
export_allowed(payload: dict, policy: dict) -> dict
```

`request(provider, inn, fields)` возвращает
`{status, data, reason_code, requests_used: 1}` и делает не более одного
запроса. Это внутренний транспортный контракт и точка инъекции в офлайн-eval,
не аргумент для исполняемого кода через CLI/MCP. Ledger передаётся общим всем
параллельным вызовам в одном бюджетном контексте. Для разных политик нужны
разные ledgers: смена политики того же ledger запрещена.

Потоки резервируют счётчик запроса и стоимость до dispatch под общим lock.
После завершения резерв переходит в used, включая timeout, неизвестную ошибку
и некорректный ответ. Возврата стоимости по предположению о бесплатной ошибке нет.
Значения reserved/used доступны в результате; lock не сохраняется в JSON.

401/403 не повторяются и не запускают fallback. 402/429 нормализуются как
`quota_exhausted`; 500/502/503 как `unavailable`, 504 как `timeout`.
Один повтор `unavailable`/`timeout` допускается только при `transient_retries: 1`
и оставшемся бюджете. 429 повторно к тому же поставщику не отправляется.
Переход Checko → DaData возможен один раз, только если причина включена в
`fallback_on` Checko, DaData включена, разрешает все запрошенные поля и бюджет
позволяет запрос. Неизвестный статус/произвольное сообщение провайдера не
интерпретируется как доказанный лимит тарифа.

Если повтор не получил резерв из-за индивидуального лимита Checko, последняя
причина реального ответа сохраняется для проверки явного fallback. Сам отказ
резерва не считается сетевым запросом и не списывает стоимость. DaData проходит
собственную проверку разрешённых полей, включения и оставшегося бюджета;
исчерпание общего бюджета не разрешает дополнительный платный запрос.

История содержит только provider, fields, time, cost_units и нормализованные
коды причин. Ошибки/ответы транспорта не копируются целиком. Ключи, auth,
окружение не сохраняются; повторённые известные секреты удаляет общий redaction.

## Сохранение и экспорт

`collector.provider_metadata(capture)` возвращает сохранённый маркер
`_provider_policy = {schema_version: 1, policy, results}`. Config читается при
создании capture, не во время render. Маркер сохраняет ограничение даже если
платный источник не дал данных. Partial/cancel/refresh checkpoints должны
копировать его до materialization; снятие текущей настройки не снимает права
с ранее сохранённых ограниченных данных.

Только отсутствие ключа `_provider_policy` означает запуск без сохранённой
политики. Любое присутствующее некорректное значение (включая `null`, пустой
объект, неверную версию или невалидную policy) отвергается до записи пакета,
создания документа/артефакта и выдачи сравнения. Ошибка не повторяет содержимое
маркера. Dossier проверяет маркеры fetch и отдельно переданного графа независимо,
даже когда у fetch уже есть валидная policy. Версия маркера — именно integer 1;
boolean и дробное JSON-число не принимаются.

`export_allowed` создаёт отдельную **консервативную проекцию**. Содержимое
локального запуска и байты исходных capture не изменяются. Проекция включает
только разрешённые простые поля последнего успешного провайдера; вложенные
структуры, raw, производные выводы, решение и метаданные запуска исключаются.
Ограничение применяется при наличии сохранённой policy, в том числе когда
`export_fields` совпадает с `allowed_fields`: полная карточка и производные
копии ещё не имеют достаточной полевой трассировки. Это ограничение текущей
реализации, а не утверждение, что остальные независимо собранные данные
запрещены лицензией.

Dossier возвращает таблицу разрешённых полей и явную пометку об исключениях,
используя сохранённый маркер fetch или отдельного графа. Повторного risk scoring,
текущей политики и нового времени в этой ветке нет. Evidence pack экспортирует
эту же проекцию, пустой `raw/index.json` и явный `_export_policy` с omissions.
Исходные raw не копируются в пакет. Манифест и проверка целостности описывают
реально записанные байты экспортной проекции, **не полноту исходного архива**.

Persisted workflow сохраняет маркер до materialization каждого source checkpoint
и финального результата `start`, включая отмену и ошибку. При `refresh` новая
политика применяется только после завершения источника `агрегатор` в текущем
capture. Обновление других источников и продолжение прерванной операции
сохраняют прежний маркер. Если текущая настройка удалена, старые ограничения
остаются; снятие настройки не означает разрешения экспорта исторических данных.

`render` и `export` используют сохранённый fetch через dossier, включая фильтрацию
переданных сохранённых fin/assessment. Они не перечитывают текущую политику и не
пересчитывают риск. Наличие новой настройки после создания запуска без policy
не меняет его экспорт задним числом. Внутренний `resume` возвращает полные
локальные данные вместе с ограничением; это не экспортная проекция.

`save_snapshot` для любого сохранённого `_provider_policy` возвращает ошибку
`provider_snapshot_export_restricted` с run_id и revision, без вызова fingerprint
и без создания артефакта. Текущий snapshot не поддерживает идентичность
частичного экспорта. Для разрешённой проекции доступны markdown, json и docx;
исходные ревизии и raw остаются неизменными. Пустой или повреждённый маркер также
не разрешает snapshot. Запуски без маркера сохраняют прежний формат снимка.

Политика оператора не подтверждает права поставщика, условия тарифа, право
передачи персональных данных или коммерческую лицензию. Реальные договоры и
актуальные условия провайдеров в этой реализации не проверялись. Живые платные
запросы не нужны для офлайн-проверок и в acceptance-eval не выполняются.

Проверка: `python3 eval/run_provider_policy_eval.py` и существующие fetch, graph,
dossier, evidence_pack, import compatibility evals.
Интеграция workflow: `python3.12 eval/run_provider_workflow_eval.py` и
`python3.12 eval/run_run_workflow_eval.py`; только офлайн-фикстуры и временный store.
