# Отдельные сценарии: ИП, мониторинг, батч, проверка без запроса

**Расширяет SKILL.md. Читать, когда сработал триггер сценария:**
ИНН из 12 цифр → «Проверка ИП» (обязательно, до сбора: у ИП другой объект проверки и два поиска в ФССП); просьба следить за контрагентом → «Мониторинг»; список или файл с ИНН → «Батч»; ИНН замечен в документе, а человек ни о чём не просил → «Проверка без запроса» (там же граница, за которой нужно согласие).

## Проверка ИП (12-значный ИНН)

ИП — другой объект: отчётности нет, адреса нет, зато есть статус самозанятого и внесудебное банкротство физлиц. `fetch_counterparty.py` сам разводит по длине ИНН (поле `тип` в выводе): для ИП риски идут через `mode=search-ip` (дефект до 1.4.0: по ИП молчали). Композитный светофор ИП:

- **Возраст/статус** (ЕГРИП ✅, egrul.nalog.ru) — действующий ли, когда зарегистрирован.
- **НПД-статус** — самозанятый ли (npd.nalog.ru check-status, официальный API; с не-РФ IP недоступен — «не проверено»).
- **Спецрежим + ССЧ** (pb.nalog.ru, search-ip) — УСН/патент, численность.
- **МСП** (✅ верифицирован) — в реестре и категория; **исключение из реестра = стоп-сигнал** 🟡 минимум.
- **Дисквалификация** — спецреестры/браузер.
- **checko entrepreneur** (если есть ключ) — ~80% картины ИП одним запросом.
- **ФССП — обязательно ДВА поиска** (браузер): ИП как юрлицо по ИНН + физлицо по ФИО + дата рождения + регион. Официальный API ФССП отключён с 10.03.2022 — токен-API больше не существует.
- **ЕФРСБ** (браузер) — включая **внесудебное банкротство физлиц** (его нет в арбитражной картотеке).
- **Контракты ЕИС** — выигранные закупки как сигнал «живой бизнес» (противовес пустышке).
- **ЕРКНМ** (плановые проверки) и **РНП** — офлайн-сверка кэшем дампов (`registries_refresh.py --refresh`).

**Принципиально недоступно по ИП (закрыто законом, не кодом) — не выдумывать:**
- выручка/баланс — у ИП нет публичной отчётности; финансовый профиль кодом неприменим, ответ — «не проверено»;
- налоговая задолженность — спецреестр ФНС публикует её только по юрлицам (ст. 102 НК РФ);
- адрес ИП — закрыт 152-ФЗ «О персональных данных» → сигналы «массовый адрес» и «недостоверность адреса» к ИП **неприменимы**, чеклист однодневки для ИП считается без них;
- краевой случай `ОгрДоступ` (ограничение доступа к сведениям от ФНС): «не нашёлся» ≠ «не существует» — помечать отдельно, не считать отсутствием записи.

## Мониторинг (снимки + diff, офлайн)

Раньше «поставить на мониторинг» было обещанием без механики. Теперь механика есть:

1. **Снимок перед каждой крупной отгрузкой:** `python3 scripts/fetch_counterparty.py <ИНН> --save` — сохраняет в `~/.cache/inn-check-ru/snapshots/<ИНН>/<дата>_<время>.json` **отпечаток**: поля, по которым идёт дифф, состояния источников и SHA-256 остального (≈1,8 КБ вместо 8,9 КБ, и в хранилище не оседают чужие персданные сверх нужного). `--режим всё` подставляется автоматически, иначе снимок был бы неполным. `--снимок полный` возвращает старое поведение — весь JSON целиком.
2. **Сравнение:** `python3 scripts/diff_counterparty.py <ИНН>` — два последних снимка → JSON изменений; `--human` — светофорная карточка изменений в формате killer-карточки. Можно и вручную: `--a старый.json --b новый.json`.
3. **Что ловит (leading indicators, теперь с датами «было/стало»):** смена статуса на ликвидацию/реорганизацию 🔴; появление недостоверности сведений 🔴 (снятие — инфо); смена руководителя 🟡 (2+ смены за год по истории снимков — «частая смена директора» 🟡); смена адреса 🟡; появление налоговой задолженности 🟡; новый год отчётности с ухудшением — ЧА ушёл ниже нуля 🔴, выручка упала больше порога fin_scoring 🟡 (пороги импортируются из `fin_scoring.py`, не дублируются); изменения в блоках МСП/спецреестров, если они собраны.
4. **Чего не ловит:** суды и банкротства снимками не покрываются (скрипт их не собирает) — перед крупной отгрузкой они проверяются отдельно, по каскаду.

Без изменений diff честно отвечает «изменений нет»; с одним снимком — «сравнивать не с чем, снимок сохранён, вернитесь позже». Ритм: снимок при онбординге контрагента, затем перед каждой крупной отгрузкой — и diff вместо полной перепроверки.

5. **Список наблюдения и расписание:** `python3 scripts/watchlist.py --добавить <ИНН> --профиль <id>`, затем `--прогон` (по всему списку: снимок → дифф → отчёт только по изменившимся и по тем, у кого проверка не состоялась). `--только-изменения` — тихий режим для крона. `--установить-расписание` печатает готовые строки crontab и launchd plist с путями текущей установки; **ничего не ставит само** — правка расписания остаётся решением пользователя.

**Важно про мониторинг:** «изменений нет» — утверждение только о том, что проверено. Если источник перестал отвечать, дифф говорит об этом отдельной строкой, а не молчит: пропавший источник и отсутствие изменений — разные новости.

## Батч: проверить базу контрагентов разом

`python3 scripts/batch_check.py контрагенты.csv --профиль отсрочка` — колонка с ИНН определяется по заголовку (или `--колонка N`, или список ИНН аргументами, или `--stdin`). По каждому — быстрая проверка и вердикт профиля; на выходе markdown-таблица (или `--csv` / `--json`), отсортированная так, что наверху опасное и непроверенное: 🔴, затем «проверка не состоялась», затем 🟡 и 🟢. Дубли схлопываются с пометкой, невалидные ИНН не выбрасываются молча — попадают в таблицу со статусом «некорректный ИНН». `--дальше` догружает досье по тем, кто не 🔴. `--продолжить <файл>` дописывает результаты, пропуская уже **успешно** проверенные ИНН: непроверенные перепроверяются, иначе таймаут навсегда остался бы дырой в базе.

Для владельца с сотней контрагентов это первая точка, где инструмент показывает ценность целиком, а не по одному ИНН.

## Проверка без запроса

Принцип «не ждёт вопроса» заявлен в описании скилла — здесь под ним механика. Триггером перестаёт быть только фраза человека: пришёл счёт на оплату, договор на подпись, выгрузка контрагентов из 1С, письмо с реквизитами — ИНН в этом тексте уже виден, и проверка запускается сама, **до оплаты, а не после**.

1. **Извлечь ИНН из документа:** `python3 scripts/extract_inn.py счёт.txt --только-новые` (или `--stdin`, или несколько файлов сразу). Форматы: текст, CSV/TSV, HTML, JSON, DOCX; PDF стандартная библиотека не читает — скрипт честно говорит «не поддерживается, передайте текст», а не делает вид, что прочитал. По каждому найденному ИНН: контекст ±80 символов (видно, чей это ИНН — поставщика, покупателя или субподрядчика), тип (ЮЛ/ИП по длине) и пометка `новый` / `уже проверялся` — по снимкам в `~/.cache/inn-check-ru/snapshots/` и списку наблюдения.
2. **Прогнать только новых:** `--проверить` отдаёт новые ИНН в `batch_check.py --режим quick` (`--профиль <id>` передаётся дальше): `python3 scripts/extract_inn.py счёт.txt --проверить --профиль отсрочка`. Уже проверенные в батч не уходят.
3. **Сообщить — только если есть о чём.** 🔴 или «проверка не состоялась» по deal-killer-источникам → сказать человеку **сразу и до оплаты**, в формате killer-карточки (шаг 6). 🟢 — не шуметь: запомнить и идти дальше, снимок уже лежит в кэше. 🟡 без deal-killer'а — одной строкой в общем ответе, без разворота. Предупреждение на каждом счёте обесценивает тот единственный 🔴, который однажды придёт по-настоящему.

**Ложные ИНН режутся кодом, а не глазами.** Десять и двенадцать цифр подряд есть у номера счёта, телефона, расчётного счёта (20 цифр), ОГРН (13), КПП (9) и у «КПП+ИНН слитно» (19) — без верного контрольного числа ФНС это не ИНН. Скрипт отбрасывает такие кандидаты с причиной (`--отбракованные` показывает, что именно отброшено и почему), ловит запись с пробелами внутри числа («ИНН 7707 083893», неразрывный пробел из вёрстки), связку «ИНН/КПП 7707083893/773601001» и колонку CSV. **Не подставляй в проверку число, выхваченное из текста на глаз** — прогони через скрипт: ошибка в одной цифре даёт чужую компанию, а чужая карточка хуже, чем её отсутствие.

**Граница проактивности (соблюдать обязательно).**
- Порог — **новый контрагент, а не каждый ИНН в документе**. Помеченные `уже проверялся` на лету не перепроверяются: для них есть мониторинг (`watchlist.py --прогон`) и снимок перед крупной отгрузкой.
- Выгрузка на сотни ИНН — **не повод для автопрогона**. Это батч, и он запускается с согласия человека: эндпоинты ФНС бесплатны, и уважение к источнику — часть работы, а не вежливость (`batch_check.py`, по умолчанию 3 потока).
- Свой собственный ИНН пользователя и ИНН, уже проверенные в этой сессии, не дёргаем повторно.
- Тихо — не значит тайно: если человек спросит, что проверялось, ответ должен быть готов (кого проверили, когда, с каким результатом). Молчание касается объёма вывода, а не факта проверки.
- Без `--проверить` скрипт полностью офлайновый: чтение документа сеть не трогает, сеть начинается только на новых ИНН.
