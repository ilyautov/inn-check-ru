# Сравнение сохранённых проверок и объяснимый граф

Читать перед сравнением сохранённых компаний или интерпретацией графа связей и ограничений покрытия.

`compare_counterparties.compare(run_ids, *, as_of, root=None)` сравнивает 2–5 различных ИНН с одинаковым явно сохранённым профилем. `as_of` — ISO 8601 с часовым поясом; результат нормализует его к UTC. Для каждого run выбирается последняя committed ревизия с `created_at <= as_of`; будущие, orphan и повреждённые ревизии не подставляются. Каждый read проходит проверку цепочки digest в `run_store`.

```python
from compare_counterparties import compare
result = compare([first_run_id, second_run_id],
                 as_of="2026-10-16T09:00:00Z", root=local_run_root)
```

CLI: `inn-check-workflow compare RUN_ID RUN_ID [RUN_ID ...] --as-of 2026-10-16T09:00:00Z --json`. `--store` остаётся локальной настройкой CLI. `counterparty_compare(run_ids, as_of)` принимает только 2–5 UUID сохранённых runs и cutoff; путь задаётся доверенным `INN_CHECK_RUNS_DIR`. Инструмент offline/readOnly, возвращает стандартный workflow envelope. Коды `ComparisonError`, включая `export_restricted`, сохраняются в `error.code`.

Результат schema 1: `profile`, `as_of`, `subjects`, `criteria`, `coverage_differences`, `limitations`. `subjects` фиксирует конкретные run/revision/saved_at. Каждая строка `criteria` содержит исходный `field`, ячейки по ИНН, ссылки `evidence_ids` и `periods_comparable`. Ячейка содержит `state`, реальные `facts` со временем, периодом, единицей, происхождением, raw availability и ID. Поле `favourable_states` пусто: это матрица доказательств, а не новый набор финансовых правил. Универсального рейтинга нет.

Нет сети, записи, обновления кэша, пересчёта финансов или профиля. Отсутствующие доказательства сохраняются как `unknown`; исходные неприменимость и конфликт остаются отдельными состояниями. Неизвестные или отличающиеся периоды не объявляются сопоставимыми. Факты из будущих наблюдений/публикаций/дат действия и просроченные факты дают `unknown`, как и зависимые от них вычисления. Устаревшее наблюдение остаётся в исходном run; сравнение не заявляет новое текущее решение. Старые записи без evidence показывают `legacy_untraced` и не получают вымышленных claim IDs.

Ошибки `ComparisonError` имеют `code` и безопасное русское `message`: `invalid_subject_count`, `duplicate_subject`, `profile_mismatch`, `revision_unavailable`, `invalid_as_of`, `invalid_evidence`, `export_restricted`. `RunStoreError` сохраняет ошибки идентификаторов, доступа и целостности. Адаптеры оборачивают их в стандартный envelope. Сравнение является выдачей производных доказательств: runs с сохранённой `_provider_policy` отказывают с `export_restricted`, поскольку действующая проекция провайдера исключает производные claims. Исходный локальный run остаётся доступен. Политика, настроенная только после сохранения обычного run, его задним числом не ограничивает.

## Граф

Присутствующий, но повреждённый `_provider_policy` (включая `null`) приводит
к `ComparisonError.code=invalid_captured_provider_policy` до выдачи критериев.
Ошибка не содержит значения маркера; запуск без самого ключа остаётся совместимым.

Все прежние ключи JSON сохраняются. Ребро дополнительно имеет `edge_type`, `evidence_ids`, `effective_at`, `origin_family`, `evidence_status` и `source_pointer_status`.

| Прежний тип | edge_type | Смысл |
|---|---|---|
| адрес | common_address | Общий адрес, не владение |
| общий_директор | common_director | Совпадение руководителя / его связей |
| общий_учредитель | common_founder | Совпадение физического лица / его связей |
| правопреемство | succession | Связь правопреемства |
| владелец | ownership | Компания → её юридический учредитель, направление `owned_by` |

Обычный ответ Checko не содержит канонических evidence IDs и raw pointers. Они не сочиняются: `evidence_ids=[]`, `effective_at=null`, `evidence_status="unknown"`, `source_pointer_status="raw_unavailable"`. Указание `origin_family="checko"` описывает наблюдаемого поставщика, а не независимость происхождения. Старая tier-маркировка сохранена для совместимости; она сама по себе не является проверкой первичного источника.

Offline-граф может передавать канонический `_evidence` и ID на ребре. Поддержка принимается только при валидной evidence-схеме/ID, `knowledge=known`, доступном raw pointer и точном совпадении `field="graph.<edge_type>"`, `value={"from":...,"to":...,"edge_type":...}` с ребром. Чужие/повреждённые ссылки не поддерживают вывод. `ownership_chains` содержит только такие подтверждённые сегменты юридического владения; это не вывод о конечном бенефициаре или контроле. Общий адрес не становится владением даже при входном `edge_type="ownership"`.

`frontier` перечисляет неразвёрнутые связи с `from`, `to`, `depth`, `stop_reason`: `depth`, `budget`, `max_nodes`, `unavailable`, `signal`, `intersection`; для ручного графа без данных о полноте — `unknown`. `усечено`, `обход.полный`, `не_проверено` сохраняют неполноту. Budget не превышает 25, даже если передать больше. Недоступная карточка и предел глубины не превращаются в «связей нет». Offline-нормализация не стирает исходную frontier/неполноту; полнота требует явного согласованного `усечено=false`, `обход.полный=true` и отсутствия frontier/stop_reason.

Досье выводит виды связей, даты, происхождение, ссылки и frontier отдельными таблицами, с оговоркой, что ассоциация не доказывает владение. Экспорт с captured provider policy по-прежнему проходит раннюю закрытую проекцию до подготовки evidence и пересчёта.

Юридический учредитель из `Учред.ЮЛ` без ОГРН не исчезает: имя и ИНН, когда
они есть, сохраняются в `frontier` с `edge_type=ownership`,
`reason_code=owner_ogrn_unavailable`, `stop_reason=unavailable`. Текущий обход
соседей требует ОГРН и такую запись не запрашивает. Повреждённые записи также
добавляют пробел проверки. В обоих случаях `обход.полный=false`; неизвестный
ОГРН и подтверждённая цепочка владельцев не выдумываются.

Проверки: `python3 eval/run_compare_eval.py`, `python3 eval/run_graph_eval.py`, `python3 eval/run_dossier_eval.py`, `python3 eval/run_profiles_eval.py`. Корпус синтетический; корректный JSON и тесты не доказывают, что реальные пользователи поняли выбор компании (эмпирический этап Phase 7 отдельно).
