# Changelog скилла

**История версий. Читать только тогда, когда спрашивают, что изменилось между версиями** — для самой проверки контрагента она не нужна и в SKILL.md занимала контекст при каждом запуске. Машинный источник истины — `CHANGELOG.md` в корне репозитория; здесь короткая выжимка по версиям скилла.

- **1.10.0** (22.09.2026) — «волна 4 и поиск по дампам»: `opendata_index.py` строит локальный бинарный индекс поверх выгрузок ФНС (`snr`/`sshr2019`/`paytax`) и отдаёт по ИНН среднесписочную численность, спецрежимы и уплаченные налоги — двоичным поиском по файлу, без БД (тринадцатый источник `дампы_фнс`; признак `ндс_к_выручке` перестал быть вечным «не проверено»). **SKILL.md разрезан** 84 КБ → 53 КБ: справочное в `references/`, каждый файл с поводом «когда читать», ссылки и релизный архив под гейтом. **Три профиля цели** — `получаю_предоплату` (деньги уже пришли: важна не платёжеспособность, а риск вернуть платёж), `тендер` (РНП — стоп), `цепочка_поставки` (вопрос про 2-3 звена, по одному светофор не выдаётся). **Ленивый обход графа**: бюджет запросов, остановка на значимом сигнале и на пересечении с известными; усечённый граф перестал притворяться полным. **Ретроспектива**: `retro_verdict.py --дата` считает светофор по снимку той даты — снимок новее не берётся, сеть не трогается. «Нет записи» нигде не читается как «нет признака».
- **1.9.0** (22.09.2026) — «норма, вычет и документ» (волна 3 роадмапа): **отраслевые нормы** — 1,4 млн компаний из открытых дампов ФНС свёрнуты в 5480 групп (ОКВЭД2 × регион × размер), выручка сравнивается с перцентилем своей группы, а не висит в воздухе; группы с n < 20 не публикуются, а смещённые (среднее и крупное собраны только по субъектам МСП) возвращают предупреждение вместо перцентиля (`benchmarks.py`, `opendata_refresh.py`); **признаки «бумажного» НДС** — 15 признаков из уже собранного, языком фактов, без налогового вывода (`paper_vat.py`), плюс профиль `ндс_вычет`; **досье осмотрительности** в Markdown и DOCX чистым stdlib — что было видно на дату проверки, с хешем входа (`dossier.py`); **проверка без запроса** — ИНН вынимается из счёта, договора, письма и выгрузки, новые уходят в quick-батч (`extract_inn.py`); MCP вырос с 9 до 13 инструментов. Починено: ГИР БО публикует в тысячах рублей, а два скрипта считали их рублями — из-за этого спала проверка уставного капитала и мёртвой была ветка «УСН ниже порога»; бумажный НДС выписывал признак технической компании банкам, которые отчётность не сдают по закону; досье писало «все источники ответили» там, где сведений о них не было; `ci.yml` вообще не разбирался как YAML.
- **1.8.0** (19.09.2026) — «скорость и охват» (волна 2 роадмапа): фазы сбора и **ранний выход** — найден deal-killer на quick-фазе, досье не собирается (`--режим quick|полный|всё`), параллельный сбор внутри фазы (~1.5×), quick укладывается в 2–4 с; **реестр дисквалифицированных лиц ожил** — найден рабочий эндпоинт `disqualified-proc.json` (без капчи и токена), сверка по ФИО руководителя с честной оговоркой «без даты рождения — не идентификация»; **перечень Росфинмониторинга починен** — XML-URL умер, перечень взят со страницы каталога (23 803 записи, четыре раздела), раздел попадает в результат сверки; батч по CSV (`batch_check.py`); мониторинг: отпечатки вместо полных снимков (−80% и меньше персданных), список наблюдения и расписание (`watchlist.py`); MCP вырос с 6 до 9 инструментов (`counterparty_verdict` отдаёт сразу светофор). Дифф теперь отличает «источник перестал отвечать» от «изменений нет».
- **1.7.0** (19.09.2026) — «перестать тихо врать» (волна 1 роадмапа): живой прогон показал, что 7 из 8 риск-флагов pb парсились по угаданным именам полей и всегда были `null` при статусе «ok». Реестр источников `scripts/sources.py` (дескриптор: контракт полей, канарейка, tier, профили); три состояния источника `ok / пусто / не проверено` + `_итог_проверки` («проверка не состоялась», если больше половины deal-killer-источников не проверено); парсеры против записанных ответов ФНС и тест дрейфа схемы (`eval/run_fetch_eval.py`, фикстуры `eval/fixtures/net/`); `check_access.py` — probe доступности с кешем, влияет на план сбора; `install_ca.py` — корень УЦ Минцифры с проверкой отпечатков (fedsfm/rosstat открылись); профили цели проверки `data/profiles_ru.json` + резолвер `profiles.py` (`нейтрально` по умолчанию — без вердикта); `--профиль` в fetch; канон в колесе PyPI; еженедельный CI канареек. Известное: URL XML-перечня РФМ отдаёт 404 — сверка по РФМ «не проверено» до починки.
- **1.6.1** (19.09.2026) — лендинг inn-check-ru.aifrontier.tech (docs/, 6 страниц под поисковые кластеры); инфраструктурная, логика не менялась.
- **1.6.0** (19.09.2026) — «стандарт флагманов» (инфраструктурная): social preview из актуальных счётчиков с CI-гейтом; релизный ZIP скилла по тегу (`release.yml`); манифесты агентов (codex/cursor/gemini) и `server.json` для MCP Registry; security/supply-chain workflows (gitleaks, запрет секретных файлов, pip-audit); версионный гейт «одна версия везде»; PyPI-пакет с console-командами. Логика проверки не менялась.
- **1.5.0** (19.09.2026) — «MCP-обёртка»: второй интерфейс поверх движка в том же репо — `mcp/server.py` (FastMCP, 6 read-only инструментов: counterparty_fetch, counterparty_fin_scoring, sanctions_check, affiliates_graph, droblenie_check, counterparty_diff) + `tools_impl.py` (subprocess поверх scripts/, ноль дублирования логики, traceback никогда не уходит в MCP-ответ) + `doctor.py` и дымовой тест; конвенции семьи schema-mcp-core сохранены стилистически (выбор и почему — в mcp/README.md).
- **1.4.0** (19.09.2026) — «ИП-пакет + бесплатные источники»: Реестр МСП верифицирован живым запросом (рабочий эндпоинт `search-proc.json?query=`, пометка «не верифицировано» снята); разведение ИП/ООО (12-значный ИНН → pb `search-ip`, поле `тип`); новые блоки НПД (статус самозанятого), ЕРКНМ и РНП (офлайн-сверка кэшем дампов, `registries_refresh.py`); каскад ФССП исправлен — официальный API мёртв с 10.03.2022, для ИП два поиска; раздел «Проверка ИП» с композитным светофором и честным списком закрытых законом данных.
- **1.3.1** (19.09.2026) — консистентность принципа «одиночному источнику не верим»: tier-маркировка узлов и рёбер графа (⚠️ один источник checko / ✅ ЕГРЮЛ для цели), корневая «оговорка» о пересечении вторым источником; `--offline-граф` — связи, собранные вручную/браузером, подаются без сети и ключа (checko — заменяемый слой, ключ — ускорение); `droblenie_check.py` выдаёт предупреждение об одном источнике; офлайн-граф из дампа ЕГРЮЛ зафиксирован как направление v2 (осознанно отложено).
- **1.3.0** (19.09.2026) — «граф связей + признаки дробления»: `affiliates_graph.py` (checko API, BFS глубина 2: общие директора/учредители, соседи по адресу, правопреемство; без ключа — graceful); `droblenie_check.py` (чеклист кодом по методике ФНС, формулировочная дисциплина «N признаков, совпадающих с типовыми доводами ФНС» — никогда «это дробление»); канон порогов `data/canon_ru.json` с цитатами и датами проверки (НДС 20/15/10 млн, УСН 490,5/337,5 млн); офлайн-eval графа на фикстурах checko.
