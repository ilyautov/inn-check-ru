# Добровольные локальные метрики

Читать перед добровольной записью, агрегацией или экспортом локальных метрик.

Запись выключена по умолчанию. Установка, запуск CLI/MCP и переменные окружения не включают её. Каждая запись требует явного `--enabled`; автоматических обработчиков, сетевой отправки и инструментов MCP для метрик нет.

Оператор сам готовит JSON одного события. Используйте новый псевдоним для каждой попытки установки или повторной задачи, включая неудачи и прекращённые попытки. Метрика не подтверждает согласие участника, реальное наблюдение или понимание результата человеком.

```json
{
  "session_id": "pilot-01",
  "stage": "install",
  "active_seconds": 60,
  "waiting_seconds": 30,
  "manual_steps": 1,
  "outcome": "abandoned",
  "reason_code": "missing_optional_dependency"
}
```

Ровно семь полей обязательны. Псевдоним: `pilot-` и 1–6 цифр либо UUID. Не используйте ИНН или идентификатор реального человека. Документы, ключи, окружение и любые дополнительные поля отвергаются. Stage/outcome/reason_code принимают только значения из `STAGES`, `OUTCOMES`, `REASON_CODES` в `scripts/workflow_metrics.py`; произвольного текста нет. Время указывается приращением для этого события, отдельно активное и ожидание, от 0 до 31 дня; число ручных шагов — целое от 0 до 100000. Булевы значения вместо чисел, NaN, infinity и повторяющиеся JSON-ключи отвергаются. Входной файл должен быть обычным файлом размером не более 4096 байт.

Команды из корня репозитория:

```sh
# Без --enabled: disabled; не читается даже EVENT.json, каталог не открывается.
python3 scripts/workflow_cli.py metrics record EVENT.json --store /local/metrics --json

# Явно разрешить только эту запись.
python3 scripts/workflow_cli.py metrics record EVENT.json --enabled --store /local/metrics --json

# Прочитать существующие агрегаты, не создавая каталог или файлы.
python3 scripts/workflow_cli.py metrics summarize --store /local/metrics --json

# Вывести только envelope с агрегатами в stdout.
python3 scripts/workflow_cli.py metrics export --store /local/metrics --json

# Отдельное явное решение оператора сохранить stdout в выбранный файл.
python3 scripts/workflow_cli.py metrics export --store /local/metrics --json > metrics-summary.json
```

`--store` — доверенный локальный путь оператора к отдельному каталогу метрик, не каталог запусков с вложенной папкой. Без него используется `~/.local/share/inn-check-ru/metrics/events.jsonl`. Примеры `/local/metrics` замените своим приватным локальным каталогом. Команды не создают экспортный файл сами и ничего не отправляют. Raw export отсутствует: `summarize` и `export` возвращают один и тот же JSON envelope, в `data` только агрегаты, без событий и псевдонимов. Обычные команды работы с контрагентом не записывают метрики.

`denominators.all_starts` включает каждую наблюдаемую попытку с первого события: неудачные установки, отказы, прекращённые и незаконченные задачи тоже. Последнее событие попытки определяет её итог и причину. Стадии, время и ручные шаги суммируются по всем событиям; промежуточное завершение не перекрывает последующее прекращение. Незаписанные попытки восстановить невозможно. Пустое хранилище означает `no_observations`, нулевые счётчики и `completion.rate: null`; даже наблюдаемые события сохраняют `empirical_acceptance: not_assessed`.

Лимиты журнала — 16 МиБ и 100000 событий. Проверка обоих лимитов и полного прежнего журнала выполняется под той же блокировкой, что и добавление. На границе новая запись отвергается без изменения существующих байтов и агрегатов; старые неудачи или прекращённые попытки не удаляются ради места. Повреждённый журнал не ремонтируется автоматически, счётчики недоступны вместо частичного результата. Каждое добавление проверяет весь ограниченный журнал; стоимость растёт с его размером.

На POSIX открытие каталога и файла привязано к дескрипторам; symlink, FIFO и hardlink в хранилище отвергаются, новые каталог/файл создаются с запрошенными правами 0700/0600. Чтение не создаёт lockfile. Ограничения: кооперативные локальные writers; поведение NFS, подмена данных вредоносным процессом того же пользователя и атомарность при отключении питания не гарантируются. На Windows проверки reparse points не устраняют same-user TOCTOU; выполнение на Windows этим изменением не проверено.

CLI возвращает код 0 при отключённой/успешной записи и читаемом/пустом агрегате; 2 при недопустимом входе или повреждённом журнале; 1 при недоступном хранилище. Ошибки содержат только контролируемый код и сообщение, без содержимого входного файла или его пути. Эксперименты с людьми, документами и исходами учитываются отдельно в `docs/research/2026-10-16/experiment-status.json`.
