# inn-check-ru: инструменты агента для поиска информации о компании по ИНН

> 🇬🇧 [English version](README.en.md)

Скилл, MCP-сервер и CLI для Claude, Codex и других агентов. Даёте ИНН, и агент сам обходит ЕГРЮЛ, «Прозрачный бизнес», бухотчётность ГИР БО, Федресурс, реестры ЦБ, санкционные списки и ещё полтора десятка реестров. На выходе досье: жива ли компания, кто владеет и руководит, выручка и долги, признаки банкротства, связанные фирмы. Суды, ФССП и банкротство ИП требуют браузерного или ручного шага; капчу проходит пользователь. Банкротство юрлиц собирается отдельным адаптером с явно указанным охватом.

В чём фишка: цифры считает код, а не модель. У каждого реестра в ответе видно, что он сказал: нашёл, пусто или проверить не удалось. «Ничего не нашёл» и «не смог проверить» не смешиваются, поэтому капча или упавший сайт не превращаются в «компания чистая».

## Начать с сохранённой проверки

**1.13.0 пока не опубликована.** Новый workflow доступен в этой ветке и локально собранном колесе. Команды PyPI `@latest`, ссылки `releases/latest` и каталог плагинов ниже относятся к опубликованным версиям и не гарантируют эти возможности.

Из корня этой ветки, Python 3.10+:

```sh
python3 -m venv /tmp/inn-workflow-venv
. /tmp/inn-workflow-venv/bin/activate
python -m pip install .
inn-check-workflow doctor --profile нейтрально --json
inn-check-workflow cache plan --profile нейтрально --json
inn-check-workflow run start 7707083893 --profile нейтрально --json > start.json
```

Start выполняет сетевой сбор и сохраняет результат. Возьмите `run_id` из собственного `start.json`, а не из примера. Для POSIX shell:

```sh
RUN_ID=$(python -c 'import json; print(json.load(open("start.json"))["run_id"])')
inn-check-workflow run resume "$RUN_ID" --json
inn-check-workflow run render "$RUN_ID" --format markdown --json
inn-check-workflow run export "$RUN_ID" --format docx --json
inn-check-workflow events list --json
```

Resume читает сохранённую ревизию и `pending_actions` без повторного сбора. Агент показывает неизвестные факты и следующий шаг: капча, кэш, ключ, конфликт или обновление. Человек явно выбирает завершение, неполный поиск либо отказ от ручного шага. Результат привязывается к ИНН, профилю и ревизии; закрытие клиента не уничтожает run.

`render` возвращает текст в `data.content` JSON envelope; `export` пишет локальный управляемый артефакт и возвращает квитанцию с `artifact_id`, SHA-256 и исходной ревизией. Обычный отчёт не является подписанной выпиской госоргана.

Полный маршрут с Windows, настройкой хоста, ручным дополнением, UUID операции, сравнением, событиями и метриками: **[references/agent-workflow.md](references/agent-workflow.md)**. [Каналы и настройки](references/capability-matrix.md) · [Восстановление](references/workflow-recovery.md).

Для работы через скилл доступны прежняя установка `npx skills add ilyautov/inn-check-ru` и [инструкции ниже](#установка). Скажите агенту:

```text
Собери сохранённое досье компании по ИНН 7707083893, профиль нейтрально.
Покажи run_id, ревизию, источники и даты, что не удалось проверить и следующий шаг.
```

Нейтральный профиль даёт факты без светофора; для оценки сделки назовите цель, например «перед отсрочкой». Можно сравнить 2–5 сохранённых компаний одного профиля на явную дату. [Документы и выбор стороны](references/document-input.md) · [Сравнение](references/comparison.md) · [Исторический replay](references/historical-replay.md).

## Зачем

Банкротство, дисквалификация директора, ликвидация — обычно всё это открыто в ЕГРЮЛ, ФССП, картотеке арбитража и ЕФРСБ ещё до сделки. Но в одну картину это никто не сводит.

Агрегаторам одним верить нельзя. Живой тест 15.06.2026: одна компания, 5 бесплатных агрегаторов, число судебных дел — ~500 / ~1000 / ~1500. Один ещё и подмешал чужие банкротные «намерения». Поэтому здесь сверяют принадлежность ИНН, первичный источник, даты и полноту. Зеркала одного реестра не являются независимыми подтверждениями; расхождение остаётся явным конфликтом, а число совпадений не делает факт достоверным.

## Как это работает

**Знание, полярность и полнота разделены.** Канонические состояния факта: `known`, `unknown`, `conflict`, `not_applicable`. Известное отсутствие признака требует подтверждённого поиска по нужному ИНН с полным охватом; пустой ответ и капча этого не доказывают. Старые состояния транспорта `ok` / `пусто` / `не проверено` сохранены для совместимости.

Нужный неизвестный факт блокирует неподдержанный 🟢; найденный стоп-сигнал остаётся видимым при неполноте других источников. Отчётный период, дата действия, дата получения и первое наблюдение различаются. [Контракт доказательств](references/evidence-contract.md).

**Два режима сбора.** Quick проверяет стоп-сигналы, полный режим собирает расширенное досье; время зависит от сети и источников. Старый CLI использует `--режим quick|полный|всё`, workflow — `--mode`. Экспертные пороги и веса не являются валидированной вероятностью банкротства отдельной компании; историческая проверка финансовых порогов ограничена своей когортой. [Калибровка](references/kalibrovka.md).

**Источники по каскаду:** бесплатные скрипты ФНС без ключей (ЕГРЮЛ, Прозрачный бизнес, ГИР БО, МСП, НПД, ЕРКНМ/РНП, список ЦБ, спецреестры) → ФССП и суды через браузер или агрегаторы → ручной ввод.

TLS для fedsfm.ru и rosstat.gov.ru чинит `install_ca.py`: корень УЦ Минцифры с проверкой отпечатков, верификация не отключается. Гео-блок обходится только **своей** нодой с российским IP (`--прокси` или `INN_CHECK_PROXY`): общего пула у проекта нет и не будет.

**Кто видит ИНН.** Провайдер модели — он в переписке. Каждый источник — свой запрос. Санкционные перечни, выгрузки ЦБ и дампы ФНС скачиваются целиком и сверяются локально. `--офлайн` не выходит в сеть вовсе. Телеметрии нет.

[Скачать inn-check-ru.mcpb](https://github.com/ilyautov/inn-check-ru/releases/latest/download/inn-check-ru.mcpb), открыть, «Установить». Движок поставится через uv. [Скачать ZIP](https://github.com/ilyautov/inn-check-ru/releases/latest/download/inn-check-ru.zip) → Settings → Capabilities → Skills → Upload skill. Собрать самому: `python3 scripts/build_release_zip.py`.

Скопируйте `SKILL.md`, `references/`, `scripts/` и `data/` в каталог скиллов агента (например `.agents/skills/inn-check-ru/`). Без `references/` агент молча теряет ветку ИП, мониторинг и батч. Без `data/` недоступны профили, канон порогов и отраслевые ориентиры.

Распакованное `extension/` + `python3 scripts/install_native_host.py --id <ID>`. macOS, Linux, Windows. Подробно — [extension/README.md](extension/README.md).

## Использование

Обычными словами:

```text
собери досье компании по ИНН 7707083893
с кем связана эта компания
```

Слэш-команды плагина в Claude Code (профиль — вторым аргументом):

| `/inn-dossier <ИНН> [профиль]` | полное досье осмотрительности |
| `/inn-batch <файл или ИНН…>` | список, опасное наверх |
| `/inn-watch [добавить/убрать/список/прогон]` | мониторинг изменений |
| `/inn-retro <ИНН> <ГГГГ-ММ-ДД>` | светофор по снимку прошлой даты |
| `/inn-links <ИНН>` | связи и признаки дробления (ключ Checko) |
| `/inn-vat <ИНН> [предмет] [сумма]` | признаки «бумажного» НДС |
| `/inn-self <ИНН>` | как вас видят банк и покупатель |

**Один движок, несколько интерфейсов:** скилл, одноразовый CLI, сохраняемый workflow и 33 [MCP-инструмента](mcp/README.md). Ядро использует stdlib без обязательных зависимостей; SDK `>=1.30,<2` и PDF `pypdf>=6.21,<7` — отдельные extras. Start/refresh/probe обращаются к сети, manual/export/snapshot/claim/ack пишут локально; read/resume/render/status не делают скрытый сбор. Расширение обеспечивает явный native handoff ручного результата, а не весь workflow.

## Чем отличается от Контур.Фокуса и Checko

Не замена, а другая задача:

- сводит несколько источников и показывает расхождения вместо одной цифры;
- живёт внутри вашего агента, рядом с остальной работой;
- открытый код: пороги видны и настраиваются.

**Чем не является:** это оценка по открытым данным, а не юридическая или кредитная гарантия. Для крупной сделки — рабочий лист для юриста. Чего не умеет — [KNOWN_LIMITS.md](KNOWN_LIMITS.md).

## Частые вопросы

**Без API-ключей работает?** Базовый контур — да: ЕГРЮЛ, риск-флаги ФНС, финансы, МСП, НПД. Граф связей — бесплатный ключ checko или браузер. Суды, ФССП, банкротство ИП — через браузер.

**Как проверить ИП?** Так же, по 12-значному ИНН. Выручки и налогового долга ИП в открытых данных нет — по закону.

**Как проверить подписанта по доверенности?** Номер машиночитаемой доверенности — в реестре ФНС m4d.nalog.gov.ru. Отозванная доверенность обесценивает подпись.

## Куда уходят данные

Собственного сервера сбора и автоматической телеметрии у проекта нет. Добровольные локальные [метрики](references/local-metrics.md) выключены по умолчанию и экспортируют только агрегаты по явной команде. Документы/OCR обрабатываются локально. При сборе запросы с реквизитами уходят — в открытые реестры: сайты ФНС (egrul, pb, bo, rmsp, service, npd), zakupki.gov.ru, pd.rkn.gov.ru, digital.mchs.gov.ru, websbor.rosstat.gov.ru, bankrot.fedresurs.ru и fedresurs.ru, clearspending.ru, reestr.nostroy.ru и reestr.nopriz.ru. Если вы сами задали ключ — ещё api.checko.ru и suggestions.dadata.ru. Санкционные списки и открытые данные скачиваются целиком и сверяются на вашей машине. Кэш — в `~/.cache/inn-check-ru/`, сохранённые workflow runs — в `~/.local/share/inn-check-ru/runs`, если хост не настроил другой каталог. Отдельный запрос TSA передаёт внешний хеш только при явном включении; целостность архива не доказывает истинность источника. Если включён свой прокси, он видит, какие ИНН вы проверяете.
