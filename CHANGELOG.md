## [1.3.0] — 2026-09-19

«Граф связей + признаки дробления»: аффилированность кодом, с формулировочной дисциплиной судов.

### Added
- `scripts/affiliates_graph.py` — граф связей через checko API (ключ из `CHECKO_API_KEY`, бесплатный): цель → директор/учредители → их компании (`СвязРуковод`/`СвязУчред`) + соседи по адресу (`МассАдрес`) + правопреемство; BFS глубина 2, лимит 100 узлов с пометкой «усечено»; defensive-парсинг схемы v2/company (документация 19.09.2026), нераспарсенное — в `не_проверено`; без ключа — честное «не проверено», exit 0.
- `scripts/droblenie_check.py` — чеклист признаков дробления кодом: общий директор/учредитель, единый адрес, идентичный ОКВЭД, все на УСН, «каждая под порогом НДС — группа над ним», группа над лимитом УСН, численность ~0 при выручке. Вывод всегда «N признаков, совпадающих с типовыми доводами ФНС по спорам о дроблении (письмо БВ-4-7/8051@ от 16.07.2024)» — никогда «это дробление». Severity: 3+ → 🟡, 5+ → 🔴. Выручка — из ГИР БО (через importlib fetch_counterparty, тыс. руб → руб) или из файла `--выручка` для офлайна; честное «по N из M компаний».
- `data/canon_ru.json` — канон порогов с цитатами: НДС-освобождение УСН 20 млн (2026) / 15 млн (2027) / 10 млн (2028), лимит УСН 490,5 млн, переходный 337,5 млн, УК 10 000 ₽; каждое число — `источник_url` + `дата_проверки`. Скоринг читает пороги отсюда; файл битый/отсутствует → «не проверено». Идея канона — из openaccountants/openaccountants.
- `eval/run_graph_eval.py` + фикстуры `eval/fixtures/graph/` (синтетические ответы checko: группа из 4 компаний 4×18 млн = 72 млн при пороге 20 млн → 🔴; здоровая контрольная → 🟢; канон отсутствует → «не проверено»), шаг в CI.
- SKILL.md — раздел «Аффилированность и признаки дробления», слой графа в каскаде.

## [1.2.0] — 2026-09-19

«Мониторинг + международные санкции»: мониторинг из обещания стал механикой, санкционный контур — три офлайн-списка.

### Added
- `scripts/diff_counterparty.py` — мониторинг изменений по снимкам: сравнение двух последних (или `--a/--b`), JSON изменений `{поле, было, стало, severity, дата_было, дата_стало}` и светофорная карточка `--human`. Ловит: смену статуса (🔴 ликвидация/реорганизация), руководителя (🟡, 2+ смены за год — «частая смена директора»), адреса, недостоверность сведений (🔴/инфо), налоговую задолженность, новый год отчётности с ухудшением (ЧА < 0 🔴, падение выручки 🟡 — пороги импортируются из fin_scoring), изменения МСП/спецреестров.
- `fetch_counterparty.py --save` — снимок проверки в `~/.cache/inn-check-ru/snapshots/<ИНН>/<дата>_<время>.json`.
- `scripts/sanctions_check.py` — международные списки: OFAC SDN (CSV, схема верифицирована на живом файле 19.09.2026) и EU Consolidated list (XML, схема верифицирована; устойчив к обрезанной недокачке — разбирает часть и честно предупреждает). `--refresh` обновляет все списки независимо, сверка идёт по всем загруженным, у каждого совпадения — список-источник и дата кэша.
- `eval/run_diff_eval.py` + фикстуры `eval/fixtures/snapshots/` (смена директора / статус→ликвидация с ухудшением финансов / без изменений), шаг в CI.
- `KNOWN_LIMITS.md` — честный список ограничений со статусами (требует РФ-IP / планируется / осознанно отложено), ссылка из README.
- SKILL.md — раздел «Мониторинг» (механика снимков и diff), санкционный контур РФМ+OFAC+EU с пометкой про вторичные санкции для экспортных сделок.

### Changed
- Пороги fin_scoring вынесены в константы модуля — их импортирует diff_counterparty, магические числа не дублируются.

## [1.1.0] — 2026-09-19

«Глубокая проверка»: числа считаются кодом, новые источники помечаются статусом верификации.

### Added
- `scripts/fin_scoring.py` — финансовый профиль кодом из строк ГИР БО: чистые активы < 0 два года подряд (🔴 deal-killer, ст. 30 ФЗ-14), ЧА < уставного капитала, автономия < 0.1, ликвидность < 1, падение выручки > 50%, убыток 2+ года, транзитный профиль (рост выручки > 300% при численности ~0). Каждый флаг — с сырыми строками баланса; нет строк — честное «не проверено».
- `eval/` — офлайн-eval `fin_scoring.py` на 3 синтетических фикстурах (здоровая / ЧА<0 / транзит), шаг в CI.
- `scripts/sanctions_check.py` — офлайн-сверка с перечнем Росфинмониторинга (террористы/экстремисты): кэш XML в `~/.cache/inn-check-ru/`, точная сверка по ИНН, нормализованная по ФИО (с пометкой «ручная сверка по дате рождения»), предупреждение об устаревании кэша > 7 дней.
- `scripts/fetch_counterparty.py` — новые блоки: Реестр МСП (rmsp.nalog.ru: статус, категория, численность) и спецреестры ФНС (service.nalog.ru: дисквалификация руководителя, налоговая задолженность >1000 ₽, недостоверность сведений); сырые строки баланса (1300/1200/1250/1400/1500) в блоке «финансы» для скоринга.
- SKILL.md — разделы «Финансовый профиль кодом» и «Признаки однодневки (чеклист по методике ФНС)» (3+ признака → 🟡, 5+ → 🔴); новые строки каскада (МСП, спецреестры, РФМ-офлайн, МЧД, залоги, Вестник/Федресурс как ранние сигналы ликвидации); шаг проверки доверенности подписанта (МЧД) в полном досье; санкционная сверка в quick-scan.

### Notes
- Эндпоинты Реестра МСП и спецреестров ФНС помечены «не верифицировано (разведка с не-РФ IP 19.09.2026)» — требуют прогона с РФ-IP; при недоступности отвечают «не проверено», не падая.
